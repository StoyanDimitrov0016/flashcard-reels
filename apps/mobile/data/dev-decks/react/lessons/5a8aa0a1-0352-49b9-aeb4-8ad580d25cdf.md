# Describing UI with components

Building a user interface by hand means writing step-by-step instructions: find this node, change its text, add a class, remove that row. Every new feature adds more instructions, and every instruction must run in the right order for the screen to stay correct. React replaces that style with a different contract, and understanding it is the foundation for everything else in this deck.

## The declarative model

In React you do not tell the browser how to change the screen. You describe what the screen should look like for the data you have right now, and React works out the changes. This is the **declarative model**: your code describes the UI that corresponds to the current state, and React computes the host changes needed to make the screen match that description. The "host" is whatever actually displays the UI, such as the browser DOM on the web or native views in React Native.

The practical payoff is that you never write manual, step-by-step DOM updates. When the data changes, you describe the new UI, and React figures out the difference between the old description and the new one.

## Components

The unit of description is a **component**: a JavaScript function that receives props and returns React elements, usually written as JSX.

```jsx
function Avatar({ name, imageUrl }) {
  return <img className="avatar" src={imageUrl} alt={name} />;
}
```

Component names start with a capital letter. That is how React tells your components (`<Avatar />`) apart from built-in host elements (`<img />`). Components can use other components, so a whole screen is a tree of components, each responsible for one piece.

React also still supports older class components, but modern React code is written with function components, and every example in this deck uses them.

## Props

**Props** are the inputs a parent passes to a child component. A component uses its props to decide what UI to return. In the example above, `name` and `imageUrl` are props, and a parent supplies them like HTML attributes:

```jsx
function Profile() {
  return <Avatar name="Ada Lovelace" imageUrl="/img/ada.jpg" />;
}
```

Props are **read-only**. A component must never modify the props object it receives. If a value needs to change over time, it belongs in state, which the next lesson introduces. Keeping props read-only is what makes a component predictable: the same props always describe the same UI.

## JSX

The markup-like syntax in these examples is **JSX**. JSX is syntax for describing React element trees using markup-like notation inside JavaScript. It looks like HTML, but it is not HTML and the browser cannot run it directly. Build tooling transforms each JSX tag into a JavaScript function call that creates an element description.

Inside JSX, curly braces switch back into JavaScript. `src={imageUrl}` passes a variable, and `{items.length}` inserts a number into text. Attribute names follow JavaScript conventions, so you write `className` instead of `class`.

## Elements are descriptions, not DOM nodes

The result of those transformed calls is a **React element**. A React element is an **immutable** description of what should appear in the UI. It records a **type** (a host tag such as `"img"` or a component such as `Avatar`), its **props**, and its **children** (which are stored as the `children` prop).

A React element is **not a DOM node**. Creating one does not touch the screen at all. It is a lightweight object that React reads later when it decides what the real UI should look like. Because elements are immutable, you never edit one after creating it; to show something different, a component returns a new element tree.

## Conditional rendering

Since a component is just a function that returns a description, you choose between different outputs with ordinary JavaScript. **Conditional rendering** means returning different element trees depending on current props or state, using normal JavaScript conditions such as `if`, the ternary operator, or `&&`.

Here is a small, realistic component that uses all of these ideas:

```jsx
function OrderStatus({ order }) {
  if (order.cancelled) {
    return <p className="muted">This order was cancelled.</p>;
  }

  return (
    <section>
      <h2>Order #{order.id}</h2>
      {order.shipped ? <p>Shipped on {order.shippedDate}</p> : <p>Preparing your items</p>}
      {order.isGift && <p>Gift wrapping included</p>}
    </section>
  );
}
```

Walk through what renders. If `order.cancelled` is true, the component returns early with a single paragraph, and nothing else in the function matters. Otherwise it returns a section with a heading. The ternary chooses between a "Shipped" and a "Preparing" paragraph. The `&&` expression adds the gift line only when `order.isGift` is true; when it is false, the expression produces `false`, which React renders as nothing.

Notice what is missing: there is no code that hides the "Preparing" paragraph when the order ships. When `order.shipped` changes, React calls `OrderStatus` again, gets the new description, and updates only what differs. That is the declarative model at work.

## Common mistakes

- **Mutating props.** Writing `props.order.shipped = true` inside a child breaks the contract that props are read-only inputs. The parent owns that data.
- **Thinking JSX is HTML.** JSX compiles to JavaScript calls, which is why attributes are camelCase and why expressions in braces must be expressions, not statements.
- **Treating elements as DOM nodes.** An element returned from a component cannot be measured, focused, or changed. Those operations need real DOM nodes, which refs provide later in this deck.
- **Using `&&` with a number.** `{count && <Badge />}` renders `0` when `count` is zero, because `0` is a valid thing to render. Write `{count > 0 && <Badge />}` instead.

## Key points

- React's declarative model: code describes the UI for the current state, and React computes the host changes to match it instead of you writing manual DOM updates.
- A component is a JavaScript function that receives props and returns React elements, usually written as JSX.
- Props are read-only inputs passed from a parent to a child; the child uses them to decide what UI to return.
- JSX is markup-like syntax inside JavaScript that build tooling transforms into calls that create element descriptions.
- A React element is an immutable description with a type, props, and children. It is not a DOM node.
- Conditional rendering returns different element trees based on props or state, using normal JavaScript conditions.
