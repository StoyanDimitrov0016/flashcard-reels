# Transitions and Actions

Not every update is equally urgent. A keystroke should appear instantly, while the search results it triggers can take a moment. Modern React lets you tell it which updates can wait, and builds on that idea to handle form submissions, pending states, and optimistic updates.

## Transitions

`startTransition` marks state updates inside it as **non-urgent**. React keeps **urgent interactions** such as typing and clicking responsive, and renders the **transition** in the background. If a new urgent update arrives, React can interrupt the transition render and start over with the latest state.

```jsx
function handleTabClick(tab) {
  startTransition(() => {
    setTab(tab);
  });
}
```

A transition does not make work disappear. It does **not** make slow computation free, and it does **not** move JavaScript to another thread. React can pause between components, but one component that runs a heavy synchronous loop still **blocks the main thread** while it runs.

`useTransition` is the Hook version. It returns an `isPending` flag along with a `startTransition` function, so the UI can show that **non-urgent work is pending**, for example by dimming the old content.

```jsx
const [isPending, startTransition] = useTransition();
```

## Deferred values

`useDeferredValue` approaches the same problem from the value side. It returns a version of a value that is allowed to **lag behind** while it changes quickly. The urgent part of the UI, such as the text input, renders with the latest value immediately, and the expensive part catches up when React has time.

```jsx
const [query, setQuery] = useState("");
const deferredQuery = useDeferredValue(query);

<input value={query} onChange={e => setQuery(e.target.value)} />
<SearchResults query={deferredQuery} />
```

## Optimistic UI

**Optimistic UI** shows the **expected result** of an operation **before the server confirms it**. Liking a post turns the heart red immediately. When the server replies, the app **reconciles**: on success the UI already looks right, and on failure it **rolls back** or corrects the value.

This reduces **perceived latency**, but it adds responsibilities. You must handle **rejections**, **conflicts** with changes made elsewhere, **duplicate submissions** from repeated clicks, and the **authoritative result** the server finally returns, which may differ from what you guessed.

`useOptimistic` models this directly. It gives you a **temporary optimistic version** of some state that is shown **while an async action is pending**. When the action finishes, the optimistic value is dropped and the real state is shown again.

```jsx
const [optimisticLikes, addOptimisticLike] = useOptimistic(
  likes,
  (current, delta) => current + delta
);
```

## Actions

In React 19 terminology, an **Action** is an **asynchronous function run as a transition**. It typically performs a **mutation**, such as saving a form, and React coordinates the surrounding UI: **pending** state while it runs, **errors**, **optimistic** updates, and **form** handling. You can pass an async function to `startTransition`, or pass one to a form's `action` prop.

```jsx
<form
  action={async (formData) => {
    await saveName(formData.get("name"));
  }}
>
  <input name="name" />
  <SubmitButton />
</form>
```

`useActionState` manages **state produced by an Action**. You give it an action function and an initial state; it returns the latest result, a wrapped action to call or pass to a form, and a flag saying whether the Action is **pending**. It fits form and mutation workflows where the result, such as an error message, needs to be shown.

```jsx
const [error, submitAction, isPending] = useActionState(async (previousState, formData) => {
  const result = await updateName(formData.get("name"));
  return result.error ?? null;
}, null);
```

`useFormStatus` gives a component **inside a form** information about that **parent form's submission**, such as whether it is currently `pending`. It must be called from a component rendered inside the `<form>`, which makes it ideal for a reusable submit button:

```jsx
function SubmitButton() {
  const { pending } = useFormStatus();
  return <button disabled={pending}>Save</button>;
}
```

## Reading resources with use

`use` lets render code **read a resource**, either a **Promise** or a **context**. When it reads a Promise that is still pending, the component **suspends** and the nearest Suspense boundary shows its fallback. When the Promise settles, React **resumes** rendering with the value. Unlike other Hooks, `use` can be called inside conditions.

```jsx
function Comments({ commentsPromise }) {
  const comments = use(commentsPromise);
  return comments.map((c) => <p key={c.id}>{c.text}</p>);
}
```

There is an important constraint. Because React may **restart or replay rendering** around a suspension, the Promise must be **stable and cached**. Creating a new Promise during render, for example by calling `fetch` inside the component body, would start a new request on every attempt and never settle into a result. Promises should come from a Suspense-compatible framework or data library, or be created outside render, such as in a Server Component, and passed down.
