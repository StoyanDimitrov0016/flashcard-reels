# Skipping work with memoization

React's default is simple: when a component renders, its children render too. Usually that is fast enough not to matter. But when a parent updates often and a child is expensive, such as a chart with thousands of points or a long table, rendering it again with the same inputs is wasted work. Memoization lets React reuse previous results. It is a precise tool, and using it well depends on understanding exactly what it skips.

## Skipping a render versus skipping a DOM update

Start with a distinction. **Preventing a DOM update** is something React does on its own: a component may **render and produce the same result**, after which React compares the output and **avoids changing the DOM**. That saves the cost of DOM work, but the component function still ran.

**Preventing a render** means the component function does not run at all. **Memoization** can **skip the component render itself** under suitable conditions. That matters when the render is the expensive part, for example because it processes a large data set.

## React.memo

**`React.memo`** (usually imported as `memo`) wraps a component so React **can skip rendering it when its props are shallowly equal to the previous props**:

```jsx
import { memo, useState } from "react";

const SalesChart = memo(function SalesChart({ data, currency }) {
  // imagine an expensive render that plots thousands of points
  return <svg className="chart">{/* ... */}</svg>;
});

function Dashboard({ data }) {
  const [note, setNote] = useState("");
  return (
    <>
      <textarea value={note} onChange={(e) => setNote(e.target.value)} />
      <SalesChart data={data} currency="EUR" />
    </>
  );
}
```

Typing in the textarea updates `note` and renders `Dashboard` on every keystroke. Without `memo`, `SalesChart` would render each time too. With `memo`, React compares the new props with the previous ones, sees that `data` is the same array and `currency` is the same string, and reuses the previous result.

`memo` only looks at props. **Context changes** and the component's **own state** can still cause it to render; if `SalesChart` read a theme context or had a zoom state, updates to those would render it as usual. And "can skip" is the right phrasing: `memo` is a performance hint, and React does not promise to skip every render.

## Why a new object defeats memoization

"Shallowly equal" means each prop is compared with `Object.is`. For strings and numbers, that compares values. For objects, arrays, and functions, it compares **references**. A **newly created object has a different reference even if its contents are equal**, so the **shallow prop comparison treats it as changed**.

```jsx
<SalesChart data={data} options={{ showGrid: true }} onPointClick={(p) => setNote(p.label)} />
```

`{ showGrid: true }` and the arrow function are created fresh on every render of `Dashboard`. Their contents never change, but their identities do, so `memo` sees changed props every time and never skips. This is the single most common reason memoization "does not work."

The fixes are to move constant values outside the component, pass primitives instead of objects, or keep references stable with the two Hooks below.

## useMemo

**`useMemo`** **caches the result of a calculation between renders until one of its dependencies changes**:

```jsx
const chartOptions = useMemo(() => ({ showGrid: true, currency }), [currency]);

const topProducts = useMemo(
  () => products.toSorted((a, b) => b.revenue - a.revenue).slice(0, 10),
  [products]
);
```

On the first render React runs the function and stores the result. On later renders, if `currency` (or `products`) is the same by `Object.is`, React returns the stored value instead of running the function again. That gives two benefits: skipping an expensive calculation, and keeping an object's **identity stable** so it does not defeat `memo` or an Effect's dependencies.

**`useMemo` is a performance optimization, not a semantic guarantee** for application correctness. React may discard cached values, for example during development or when a component suspends. Your code must produce correct results even if the calculation runs every time; memoization should only make it faster. If something breaks when you remove `useMemo`, the real bug is elsewhere.

## useCallback

**`useCallback`** **caches a function reference between renders until dependencies change**:

```jsx
const handlePointClick = useCallback((point) => {
  setNote(point.label);
}, []);

<SalesChart data={data} options={chartOptions} onPointClick={handlePointClick} />;
```

It is equivalent to `useMemo(() => fn, deps)`. It does not make the function faster to call or create; it keeps the **same function identity**. That only helps when **function identity matters**: when the function is passed to a **memoized child**, like `SalesChart`, or used as a dependency of **another Hook**, such as an Effect. Wrapping a handler passed to a plain `<button>` achieves nothing.

With `chartOptions` and `handlePointClick` stable, typing in the textarea finally skips `SalesChart` entirely.

## When useMemo makes code worse

Memoization is not free. Every `useMemo` stores a value, compares dependencies on every render, and adds code to read. **If the calculation is cheap or the dependencies change often**, memoization adds **comparison, memory, and complexity without meaningful saved work**. Memoizing `firstName + " " + lastName` costs more than it saves, and memoizing something whose dependency is a new object every render never hits the cache at all.

Measure first. If a calculation takes well under a millisecond, leave it alone.

Note that the React Compiler, now stable, can add this kind of memoization automatically at build time. Where a project uses it, hand-written `memo`, `useMemo`, and `useCallback` become much less common, but the underlying ideas, identity and shallow comparison, still explain what is happening.

## Common mistakes

- **Wrapping in `memo` while passing inline objects or functions.** The child renders every time anyway.
- **Relying on `useMemo` for correctness.** Treat it as a cache that can be cleared.
- **Memoizing everything.** Cheap calculations become slower and harder to read.
- **Expecting `memo` to block context or state updates.** It only compares props.

## Key points

- Preventing a DOM update happens when a render produces the same result; memoization can skip the component render itself.
- `React.memo` can skip rendering when props are shallowly equal to the previous props; context changes and the component's own state still cause renders.
- A newly created object has a new reference even with equal contents, so shallow comparison treats it as changed and defeats memoization.
- `useMemo` caches a calculation's result until a dependency changes; it is a performance optimization, not a correctness guarantee.
- `useCallback` caches a function reference until dependencies change, which helps when identity matters to memoized children or other Hooks.
- `useMemo` makes code worse when the calculation is cheap or dependencies change often, adding cost without saved work.
