# Objects and prototypes

JavaScript objects are collections of properties, and they share behavior through links to other objects rather than through copied class definitions. This lesson covers property keys, the prototype chain, how constructors and classes build on it, and the attributes that control each property.

## Property keys

Every **property key** is either a **string** or a **symbol**. Anything else used as a key is converted to a string first. That includes numbers: `obj[1]` and `obj["1"]` name the same property, and array indexes are string keys under the hood.

```js
const obj = {};
obj[1] = "one";
Object.keys(obj); // ["1"]
```

A **symbol** is a primitive whose every instance is unique. `Symbol("id") === Symbol("id")` is `false`, so a symbol key cannot collide with any other key, even one with the same description. That makes symbols a good way to attach properties that will not clash with other code. The language also uses well-known symbols for **protocols**: `Symbol.iterator`, for example, is the key that makes an object work with `for...of`.

## The prototype chain

Every object has an internal link to another object, its **prototype**, or to `null`. When you read a property, JavaScript looks at the object's own properties first. If the key is not there, it follows the prototype link and looks again, and keeps following links until it finds the key or reaches `null`. That sequence of links is the **prototype chain**. Reaching `null` without a match gives `undefined`.

This is how every array can call `push`: the method lives once on `Array.prototype`, and each array reaches it through its chain.

**`Object.create(proto)`** builds a new object whose direct prototype is `proto`. No constructor function runs; you simply get an empty object with the chosen link.

```js
const animal = {
  speak() {
    return `${this.name} makes a sound`;
  },
};

const dog = Object.create(animal);
dog.name = "Rex";
dog.speak(); // "Rex makes a sound", found on animal
```

## Shadowing

If an object has its own property with the same key as one further up the chain, the lookup stops at the own property. The inherited one is hidden, or **shadowed**. Assigning to an inherited data property normally creates a new own property on the object rather than changing the prototype.

```js
dog.speak = () => "Woof";
dog.speak(); // "Woof": own property shadows animal.speak
animal.speak.call(dog); // the original is still there
```

## Constructors and new

A constructor is a regular function meant to be called with **`new`**. The operator does four things:

1. Creates a fresh object.
2. Links that object's prototype to the constructor's `prototype` property.
3. Calls the constructor with the new object as `this`.
4. Returns the new object, unless the constructor explicitly returns a different object.

```js
function Point(x, y) {
  this.x = x;
  this.y = y;
}
Point.prototype.length = function () {
  return Math.hypot(this.x, this.y);
};

new Point(3, 4).length(); // 5
```

## Classes

**Classes** are clearer syntax for the same prototype mechanism, not a separate object model. The `constructor` body plays the role of the constructor function, and methods declared in the class body are placed on `ClassName.prototype`. Every instance shares those methods through its prototype chain instead of carrying its own copies.

```js
class Circle {
  constructor(r) {
    this.r = r;
  }
  area() {
    return Math.PI * this.r ** 2;
  }
}

const c = new Circle(1);
Object.getPrototypeOf(c) === Circle.prototype; // true
c.hasOwnProperty("area"); // false: area is shared
```

## instanceof and realms

**`x instanceof C`** asks one question: does `C.prototype` appear anywhere in the prototype chain of `x`? It does not check how `x` was created, only what its chain contains.

That makes it unreliable across **realms**. Each browser frame, iframe, or worker has its own global environment with its own `Array`, `Object`, and other built-ins. An array made inside an iframe links to that iframe's `Array.prototype`, so `instanceof Array` in the parent page returns `false`. Use checks that work across realms, such as `Array.isArray`, when values may come from elsewhere.

## Property descriptors

Each property carries attributes described by a **property descriptor**. There are two kinds of property.

A **data property** stores a value. Its descriptor has `value`, `writable` (can it be assigned), `enumerable` (does it show up in `Object.keys` and `for...in`), and `configurable` (can it be deleted or have its attributes changed).

An **accessor property** stores no value of its own. Instead it has `get` and `set` functions that run when the property is read or written, plus `enumerable` and `configurable`.

```js
const temp = { celsius: 20 };
Object.defineProperty(temp, "fahrenheit", {
  get() {
    return this.celsius * 1.8 + 32;
  },
  enumerable: true,
});

temp.fahrenheit; // 68, computed by the getter
Object.getOwnPropertyDescriptor(temp, "celsius");
// { value: 20, writable: true, enumerable: true, configurable: true }
```

## Object.freeze

**`Object.freeze(obj)`** locks an object: no own properties can be added or removed, none can be reconfigured, and every existing data property becomes non-writable. In strict mode, attempts to change a frozen object throw; in sloppy mode they fail silently.

The freeze is **shallow**. It applies only to the object's own properties. If a property holds another object, that nested object stays fully mutable unless you freeze it too.

```js
const config = Object.freeze({ port: 80, db: { host: "a" } });
config.port = 81; // ignored (or TypeError in strict mode)
config.db.host = "b"; // works: db itself is not frozen
```
