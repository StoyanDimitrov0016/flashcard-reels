# Truthiness and short-circuiting

`if (value)` and `value || fallback` are everywhere in JavaScript, but they don't check whether `value` is `true` - they check something looser called truthiness, and they rely on logical operators that don't always evaluate every operand. Misreading either one is a common source of bugs, especially when a legitimate value like `0` or `""` gets treated as "missing." This lesson makes both behaviors precise.

## Truthiness

**Truthiness** is how a value is interpreted when JavaScript needs a boolean - inside an `if`, a `while`, or as an operand of `&&`, `||`, or the ternary operator. Only eight values are **falsy**: `false`, `0`, `-0`, `0n`, `NaN`, `""`, `null`, and `undefined`. Every other value - including `[]`, `{}`, and `"0"` - is **truthy**.

```js
if ("") console.log("truthy"); // does not run: "" is falsy
if ([]) console.log("truthy"); // runs: an empty array is truthy
if (0) console.log("truthy"); // does not run: 0 is falsy
```

The empty array and empty object being truthy trips people up the most: "empty" does not mean "falsy" for objects, only the eight specific falsy primitives count.

## Short-circuit evaluation

`&&`, `||`, and `??` don't always evaluate their right-hand operand. Each one **short-circuits**: it stops as soon as the result is already determined, and returns whichever operand decided the outcome rather than a plain `true`/`false`.

- **`&&`** evaluates left to right and returns the first falsy operand, or the last operand if all are truthy.
- **`||`** returns the first truthy operand, or the last operand if all are falsy.

```js
function sideEffect() {
  console.log("called");
  return true;
}
false && sideEffect(); // sideEffect never runs - && short-circuits on the falsy left side
true || sideEffect(); // sideEffect never runs - || short-circuits on the truthy left side
```

This is why `condition && doSomething()` is a common idiom for "run this only if condition is truthy," and why `value || defaultValue` is a common idiom for "use value, or fall back."

## Where || falls short: nullish coalescing

The trouble with `value || defaultValue` is that it falls back for **every falsy value**, not just missing ones. If `0`, `""`, or `false` are legitimate values you want to keep, `||` discards them:

```js
function getVolume(setting) {
  return setting || 50; // bug: an explicit volume of 0 becomes 50
}
getVolume(0); // 50, not the caller's intended 0
```

**`??`** (nullish coalescing) fixes this: it returns its right operand **only when the left operand is `null` or `undefined`**, leaving every other falsy value - `0`, `""`, `false`, `NaN` - untouched.

```js
function getVolume(setting) {
  return setting ?? 50; // only missing values fall back
}
getVolume(0); // 0: kept, because 0 is not null/undefined
getVolume(undefined); // 50: falls back correctly
```

## Optional chaining

**`?.`** (optional chaining) applies the same "only null/undefined counts as missing" logic to property access and calls. If the value to the left of `?.` is `null` or `undefined`, the whole expression short-circuits to `undefined` instead of throwing:

```js
const user = { profile: null };
user.profile.name; // TypeError: Cannot read properties of null
user.profile?.name; // undefined - short-circuits instead of throwing
user.profile?.name ?? "no name"; // "no name" - chain the two together
```

`?.` also works before a function call (`callback?.()`, invoking `callback` only if it isn't `null`/`undefined`) and before array indexing (`arr?.[0]`).

## Common mistakes

- **Using `||` for defaults when `0`, `""`, or `false` are valid values.** It discards them along with real absences; use `??` when only `null`/`undefined` should trigger the fallback.
- **Assuming `[]` or `{}` are falsy because they're "empty."** Only the eight specific falsy values are falsy; every object, including empty ones, is truthy.
- **Chaining `?.` past the point where you actually need the value to exist.** `?.` suppresses the error, but code further down still has to handle `undefined` if the chain came up empty.

## Key points

- Truthiness is the boolean interpretation of a value in conditions; only `false`, `0`, `-0`, `0n`, `NaN`, `""`, `null`, and `undefined` are falsy.
- `&&`, `||`, and `??` short-circuit: they skip evaluating later operands once the result is already determined.
- `??` returns its right operand only when the left is `null` or `undefined`, unlike `||`, which falls back on any falsy value.
- `?.` stops a property access or call and produces `undefined` when the value to its left is `null` or `undefined`, instead of throwing.
