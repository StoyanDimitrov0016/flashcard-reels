# Functions and this

Functions are central to JavaScript. They are ordinary values, they come in several syntactic forms, and they receive a special `this` value whose rules often surprise newcomers. This lesson explains how functions behave as values and how `this` is decided.

## Functions are values

JavaScript has **first-class functions**: a function is a value like a number or an object. You can store it in a variable, put it in an array or object, pass it as an argument, and return it from another function.

That makes **higher-order functions** possible. A higher-order function either takes one or more functions as arguments, returns a function, or does both. Array methods like `map` and `filter` take callbacks; a factory like `makeCounter` returns a function.

```js
const double = (n) => n * 2;
[1, 2, 3].map(double); // [2, 4, 6]: map is higher-order

const multiplier = (k) => (n) => n * k; // returns a function
multiplier(3)(5); // 15
```

## Declarations and expressions

A **function declaration** is a statement that starts with the `function` keyword and gives the function a name. It is created while the surrounding scope is being set up, before any of its code runs, so it can usually be called from lines above it.

A **function expression** produces a function as part of an expression, such as the right side of an assignment. The function value only exists once execution reaches that expression.

```js
square(4); // 16: the declaration already exists

function square(n) {
  return n * n;
}

cube(2); // ReferenceError: cube is still in the TDZ
const cube = function (n) {
  return n * n * n;
};
```

## How this is decided

For a regular (non-arrow) function, **`this` is decided by how the function is called**, not where it is defined. The same function can see a different `this` on each call:

1. **Method call**: `obj.method()` sets `this` to `obj`.
2. **Constructor call**: `new Fn()` sets `this` to the newly created object.
3. **Explicit call**: `fn.call(x)`, `fn.apply(x)`, or a function made with `fn.bind(x)` sets `this` to `x`.
4. **Plain call**: `fn()` sets `this` to `undefined` in strict mode and modules, or to the global object in sloppy scripts.

A common bug comes from losing the call form. Pulling a method off its object and calling it on its own turns a method call into a plain call:

```js
"use strict";
const user = {
  name: "Ada",
  hello() {
    return this.name;
  },
};

user.hello(); // "Ada"
const f = user.hello;
f(); // TypeError: this is undefined
```

## Arrow functions

**Arrow functions** do not get their own `this`. They capture `this` **lexically** from the surrounding code, exactly like a closure captures a variable. That is why arrows are convenient for callbacks inside methods: the callback sees the method's `this`.

```js
const timer = {
  seconds: 0,
  start() {
    setInterval(() => {
      this.seconds++; // this is timer, taken from start()
    }, 1000);
  },
};
```

Arrow functions also lack the machinery for construction. They have no constructor behavior and no own `prototype` property for instances to inherit from, so calling an arrow with `new` throws a `TypeError`.

## Fixing this with bind, call, and apply

Every function inherits three methods from `Function.prototype` that control `this` explicitly.

**`call`** and **`apply`** invoke the function immediately with a chosen `this`. The only difference is how arguments are passed: `call` takes them one by one, `apply` takes them as one array or array-like value.

```js
function introduce(greeting, punctuation) {
  return `${greeting}, I am ${this.name}${punctuation}`;
}

const ada = { name: "Ada" };
introduce.call(ada, "Hi", "!"); // "Hi, I am Ada!"
introduce.apply(ada, ["Hi", "!"]); // same result
```

**`bind`** does not call anything. It returns a **new function** whose `this` is permanently fixed, and it can also fix leading arguments in advance. The bound function is handy for passing a method as a callback without losing its object.

```js
const hiAda = introduce.bind(ada, "Hi");
hiAda("."); // "Hi, I am Ada."
```

Arrow functions ignore all three for `this`: their `this` is always the one they captured.
