# Promise combinators

Real programs rarely wait on just one asynchronous operation - they fetch several resources at once, race a request against a timeout, or want to know about every outcome even if some fail. Four static `Promise` methods each combine multiple Promises into one, and each answers a different question about "what counts as done."

## Promise.all: everything must succeed

**`Promise.all`** takes an array of Promises and **fulfills with their results in input order**, but only once **every** input has fulfilled. If **any** input rejects, `Promise.all` **rejects immediately** with that reason, without waiting for the others to finish.

```js
Promise.all([
  new Promise((r) => setTimeout(() => r("a"), 30)),
  new Promise((r) => setTimeout(() => r("b"), 10)),
]).then((results) => console.log(results)); // ["a", "b"] - input order, not completion order

Promise.all([Promise.resolve(1), Promise.reject("boom"), slowThirdRequest()]).catch((error) =>
  console.log(error)
); // "boom", reported as soon as it happens - the slow third request is not awaited first
```

`Promise.all` is the right choice when you need _all_ results to proceed, and a single failure should stop you from proceeding at all - for example, loading several required pieces of a page before rendering.

## Promise.allSettled: every outcome, no matter what

**`Promise.allSettled`** also waits for every input, but instead of rejecting on the first failure, it **always fulfills**, resolving with an array describing each input's own outcome: `{ status: "fulfilled", value }` or `{ status: "rejected", reason }`.

```js
Promise.allSettled([Promise.resolve(1), Promise.reject("boom")]).then((results) =>
  console.log(results)
);
// [
//   { status: 'fulfilled', value: 1 },
//   { status: 'rejected', reason: 'boom' }
// ]
```

Use `allSettled` when partial failure is fine and you want to know about every outcome individually - for example, sending several independent notifications and reporting which ones failed, without letting one failure hide the results of the others.

## Promise.race: first to settle wins

**`Promise.race`** settles as soon as the **first** input Promise settles, with whatever outcome that one had - fulfillment or rejection. Every other input keeps running, but their eventual outcomes are ignored.

```js
Promise.race([
  new Promise((r) => setTimeout(() => r("slow"), 30)),
  new Promise((r) => setTimeout(() => r("fast"), 5)),
]).then((value) => console.log(value)); // "fast" - it settled first
```

A common use is racing a request against a timeout: `Promise.race([fetchData(), timeout(2000)])` settles with whichever one finishes first, letting the timeout "win" and reject if the real request takes too long.

## Promise.any: first success wins

**`Promise.any`** is the fulfillment-focused counterpart to `race`: it **fulfills with the first input that fulfills**, ignoring rejections along the way. It only **rejects** if **every** input rejects, and in that case rejects with an `AggregateError` collecting all the individual rejection reasons.

```js
Promise.any([Promise.reject("a"), Promise.reject("b"), Promise.resolve("c")]).then((value) =>
  console.log(value)
); // "c" - the first (and only) fulfillment

Promise.any([Promise.reject("a"), Promise.reject("b")]).catch((error) => {
  console.log(error.constructor.name, error.errors); // "AggregateError" ["a", "b"]
});
```

`any` is the natural fit for "try several equivalent sources and use whichever responds successfully first" - for example, querying several redundant servers and taking the first one that answers.

## Choosing between them

All four combinators start from the same array of Promises; the difference is only in what counts as "done" and how failure is treated:

- **`all`** - need every result; one failure should fail the whole thing immediately.
- **`allSettled`** - need every outcome; failures are informative, not fatal.
- **`race`** - need whichever settles first, success or failure.
- **`any`** - need the first success; only fail if literally everything failed.

## Common mistakes

- **Using `Promise.all` when partial failure should be tolerated.** One rejection aborts the whole combination; `allSettled` is the fit when you want to inspect every outcome regardless of failures.
- **Expecting `Promise.race` to cancel the losing operations.** It doesn't - the other Promises keep running to completion in the background; `race` just ignores their eventual result.
- **Reading `Promise.any`'s rejection as a single error.** On total failure it rejects with an `AggregateError`, whose `errors` property holds every individual rejection reason, not just one.

## Key points

- `Promise.all` fulfills with results in input order once every input fulfills, and rejects as soon as one input rejects.
- `Promise.allSettled` waits for every input and always fulfills with each input's fulfillment or rejection outcome.
- `Promise.race` settles with the outcome of whichever input settles first, fulfillment or rejection.
- `Promise.any` fulfills with the first fulfilled input, and rejects with an `AggregateError` only if every input rejects.
