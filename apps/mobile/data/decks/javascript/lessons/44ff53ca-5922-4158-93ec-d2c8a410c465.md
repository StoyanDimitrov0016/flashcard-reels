# Destructuring, spread, and iteration

Modern JavaScript has compact syntax for pulling values out of objects and arrays, spreading them into new ones, and walking through sequences. Under the hood, much of it rests on one idea: the iteration protocol. This lesson covers the syntax, the copying rules, and the protocol itself.

## Destructuring

**Destructuring** unpacks values into variables using a pattern that mirrors the shape of the data.

**Object destructuring** picks properties by name. You can rename, give defaults for missing values, and nest patterns.

```js
const user = { name: "Ada", role: "admin", address: { city: "London" } };
const {
  name,
  role: title,
  age = 30,
  address: { city },
} = user;
// name = "Ada", title = "admin", age = 30, city = "London"
```

**Array destructuring** picks values by position. It works on any iterable, not only arrays, because it consumes values one after another. Holes skip positions.

```js
const [first, , third] = ["a", "b", "c"];
const [x, y] = new Set([10, 20]); // works on any iterable

let a = 1;
let b = 2;
[a, b] = [b, a]; // swap
```

## Spread and rest

The same `...` token has two opposite jobs depending on where it appears.

**Spread** expands. In a function call or array literal it expands the items of an iterable; in an object literal it copies an object's properties into the new object.

**Rest** collects. In a parameter list or a destructuring pattern it gathers everything that remains into a single array or object.

```js
const nums = [1, 2, 3];
Math.max(...nums); // spread into arguments: 3
const more = [...nums, 4]; // spread into an array

function sum(...values) {
  // rest: values is an array
  return values.reduce((t, v) => t + v, 0);
}

const { id, ...rest } = { id: 7, a: 1, b: 2 }; // rest = { a: 1, b: 2 }
```

## Shallow and deep copies

Object spread (`{ ...obj }`) creates a new top-level object and copies the source's **enumerable own properties**. It is a **shallow copy**: if a property holds an object, the copy gets a reference to the same nested object, not a duplicate.

```js
const original = { name: "Ada", tags: ["math"] };
const copy = { ...original };
copy.name = "Grace"; // original unaffected
copy.tags.push("code"); // original.tags changes too
```

For a **deep copy**, use **`structuredClone`**. It recursively copies many built-in data types, including plain objects, arrays, `Date`, `Map`, `Set`, and typed arrays. It also handles **cyclic graphs** and preserves shared references within the copy, so nothing in the result points back into the original. Some values cannot be cloned: functions, DOM nodes, and similar values throw a `DataCloneError`, and class instances come back as plain objects without their prototype.

```js
const deep = structuredClone(original);
deep.tags.push("art"); // original.tags is untouched
```

## The iteration protocol

An **iterable** is any value with a `[Symbol.iterator]()` method that returns an iterator. Arrays, strings, `Map`, `Set`, and many DOM collections are iterable, and that single method is what lets `for...of`, spread, array destructuring, and `Array.from` consume them.

An **iterator** is an object with a `next()` method. Each call returns a result record `{ value, done }`: `value` is the next item, and `done` becomes `true` when the sequence is finished.

```js
const it = ["a", "b"][Symbol.iterator]();
it.next(); // { value: "a", done: false }
it.next(); // { value: "b", done: false }
it.next(); // { value: undefined, done: true }
```

## Generators

Writing iterators by hand means tracking position in object fields. A **generator function**, written `function*`, does that bookkeeping for you. Calling it returns an iterator without running the body. Each `next()` call runs the body until the next `yield`, hands out the yielded value, and **pauses** there, keeping all local variables intact until the following `next()`.

```js
function* naturals() {
  let n = 1;
  while (true) yield n++;
}

const gen = naturals();
gen.next().value; // 1
gen.next().value; // 2
```

This solves the problem of **lazy sequences**. Values are produced one at a time, only when asked for, so a generator can describe a huge or even infinite sequence without computing or storing it up front. The paused function remembers its own state, so there is no need to rebuild it between values.

## for...of versus for...in

The two loops look similar but iterate different things.

- **`for...of`** iterates **values** produced by an iterable, using the iteration protocol.
- **`for...in`** iterates **enumerable string property keys** of an object, including enumerable keys inherited through the prototype chain. It skips symbol keys.

```js
const arr = ["x", "y"];
for (const v of arr) console.log(v); // "x", "y"
for (const k in arr) console.log(k); // "0", "1" (as strings)
```

Use `for...of` for arrays and other collections. Use `for...in` rarely, and prefer `Object.keys` or `Object.entries` when you want only an object's own keys.
