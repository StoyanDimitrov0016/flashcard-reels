# Modules and Promises

Two features shape how modern JavaScript programs are organized and how they wait for slow work. Modules split code into files with explicit dependencies. Promises and async functions represent results that are not ready yet. This lesson covers both, ending with the tools for waiting on several operations at once.

## Modules

A **module** is a file with **its own scope**. Top-level variables in a module are private to it unless it explicitly **exports** them, and other modules must explicitly **import** what they use.

```js
// math.js
export const PI = 3.14159;
export function area(r) {
  return PI * r * r;
}

// app.js
import { area } from "./math.js";
area(2);
```

## Live bindings

An import is not a copy of a value. It is a **live binding**: a read-only view of the exporting module's variable. If the exporter later changes that variable, every importer sees the new value. Importers cannot assign to the imported name themselves; only the module that owns the variable can change it.

```js
// counter.js
export let count = 0;
export function increment() {
  count++;
}

// app.js
import { count, increment } from "./counter.js";
increment();
console.log(count); // 1: the import reflects the update
count = 5; // TypeError: imported bindings are read-only
```

## Static and dynamic imports

**Static `import` declarations** must appear at the top level with literal module paths. That restriction is the point: the whole dependency graph is known **before any code runs**. The engine can fetch and link every module up front, and tools can analyze imports without executing anything. Bundlers rely on this for combining files and for **tree-shaking**, removing exports nobody imports.

**Dynamic `import()`** is an expression you can call anywhere, with a computed path. It loads a module **asynchronously** and returns a Promise for the **module namespace object**, whose properties are the module's exports. Use it to defer loading code until it is actually needed, such as a heavy editor that opens only on click.

```js
button.addEventListener("click", async () => {
  const { openEditor } = await import("./editor.js");
  openEditor();
});
```

## Promises

A **Promise** is an object that stands for the **eventual result of an asynchronous operation**. Instead of passing a callback into the operation, you get a Promise back and attach handlers to it.

A Promise is always in one of three states:

- **Pending**: the result is not known yet.
- **Fulfilled**: the operation succeeded with a value.
- **Rejected**: the operation failed with a reason, usually an `Error`.

A Promise **settles only once**. After it becomes fulfilled or rejected, its state and result never change, and handlers attached later still receive that same outcome.

## Chaining with then and catch

**`.then(onFulfilled, onRejected)`** always returns a **new Promise**, which is what makes chains possible. The new Promise's outcome depends on what the handler does:

- **Returns a value**: the new Promise fulfills with that value.
- **Throws**: the new Promise rejects with the thrown error.
- **Returns a Promise**: the new Promise adopts it, settling the same way once it settles.

`.catch(fn)` is shorthand for `.then(undefined, fn)` and follows the same rules. Because a throwing handler turns into a rejection, an error anywhere in a chain skips the remaining fulfillment handlers and travels down to the next `catch`.

```js
fetch("/api/user")
  .then((res) => res.json()) // returns a Promise: adopted
  .then((user) => {
    if (!user.active) throw new Error("inactive"); // rejects the chain
    return user.name;
  })
  .catch((err) => console.error(err));
```

## async and await

An `async` function always returns a Promise, and inside it **`await`** unwraps Promises with ordinary-looking code. `await value` pauses the function until the value settles. On fulfillment the function resumes, in a later **microtask**, with the fulfilled value. On rejection, the `await` expression **throws** the reason, so `try`/`catch` works.

Crucially, **`await` does not block the thread**. Only the current async function is suspended. The engine returns to its caller and keeps running other code, timers, and event handlers until it is time to resume.

## Sequential versus concurrent

Awaiting inside a sequence starts each operation only after the previous one finishes, so total time is the sum of all the waits. When operations are independent, start them together and wait for all of them at once.

```js
// Sequential: about 2 seconds if each takes 1 second
const a = await loadA();
const b = await loadB();

// Concurrent: about 1 second
const [a2, b2] = await Promise.all([loadA(), loadB()]);
```

## Combining Promises

Four static methods take an iterable of Promises and return one Promise:

- **`Promise.all`** fulfills with an array of results **in input order** once every input fulfills. It rejects as soon as **any one** input rejects, with that input's reason.
- **`Promise.allSettled`** waits for **every** input to settle and never rejects because of an input. It fulfills with an array of outcome objects, each either `{ status: "fulfilled", value }` or `{ status: "rejected", reason }`.
- **`Promise.race`** settles the same way as **the first input to settle**, whether that is a fulfillment or a rejection. It is often used to add a timeout.
- **`Promise.any`** fulfills with **the first input to fulfill**, ignoring rejections along the way. Only if **all** inputs reject does it reject, with an `AggregateError` holding every reason.
