# Destructuring and spread

Pulling a handful of fields out of an object, or building a new array from pieces of an old one, used to take several lines of manual indexing and property access. Destructuring and spread syntax collapse that into a single expression - but spread's convenience hides one sharp edge worth understanding before you rely on it for copying data.

## Object destructuring

**Object destructuring** reads selected properties out of an object and assigns them to bindings, matched **by property name**, according to a pattern you write on the left of `=`. You can rename a binding, give it a default for when the property is missing, and combine both:

```js
const user = { name: "Ada", age: 32 };
const { name, age: years, country = "unknown" } = user;
console.log(name, years, country); // "Ada" 32 "unknown"
```

`age: years` renames the binding to `years`; `country = "unknown"` supplies a default because `user` has no `country` property. This same pattern works directly in function parameters, which is common for options objects:

```js
function describe({ name, age = 0 } = {}) {
  return `${name ?? "anon"} (${age})`;
}
describe({ name: "Bo" }); // "Bo (0)"
describe(); // "anon (0)" - the `= {}` default covers a missing argument entirely
```

## Array destructuring

**Array destructuring** consumes values from an iterable **by position** instead of by name, matching a pattern of variable names against the sequence of values. A gap in the pattern skips a position, and `...` collects everything remaining:

```js
const coords = [10, 20, 30];
const [x, , z] = coords;
console.log(x, z); // 10 30 - the middle value is skipped

const [first, ...others] = coords;
console.log(first, others); // 10 [20, 30]
```

Because it works on any iterable, array destructuring also works on strings, `Map` entries, and generator results, not just arrays.

## Spread vs. rest

The `...` syntax means two opposite things depending on where it appears, and it's easy to conflate them:

- **Spread** _expands_ an iterable's items, or an object's own enumerable properties, into a new context - a function call, an array literal, or an object literal.
- **Rest** _collects_ the remaining arguments, elements, or properties into a single new value, and only appears in a binding pattern (function parameters or a destructuring pattern).

```js
// Spread: expanding values outward
const nums = [1, 2, 3];
console.log(Math.max(...nums)); // 6 -> max(1, 2, 3)
const combined = { ...{ a: 1 }, ...{ b: 2 } }; // { a: 1, b: 2 }

// Rest: collecting values inward
function sum(...values) {
  return values.reduce((total, n) => total + n, 0);
}
sum(1, 2, 3); // 6

const { a, ...remaining } = { a: 1, b: 2, c: 3 };
console.log(a, remaining); // 1 { b: 2, c: 3 }
```

The syntax is identical (`...`); only the position - a call/literal versus a binding pattern - tells you which behavior applies.

## Object spread is a shallow copy

Spreading an object's properties into a new object literal (`{ ...source }`) creates a genuinely new top-level object - but it copies each property's **value** as-is. For a nested object property, that value is a reference, so the nested object is **shared**, not duplicated:

```js
const original = { name: "Ada", address: { city: "London" } };
const copy = { ...original };

copy.name = "Grace"; // fine: only affects the top-level copy
console.log(original.name); // "Ada" - untouched

copy.address.city = "Paris"; // mutates the shared nested object
console.log(original.address.city); // "Paris" - original changed too!
```

`copy` and `original` are different objects, but `copy.address` and `original.address` are the _same_ object - spreading never recurses into nested values. If you need every level duplicated, spread is the wrong tool; reach for `structuredClone` or another deliberate deep-clone approach instead (covered later, in the cloning and serialization lesson).

## Common mistakes

- **Treating `{ ...obj }` as a deep clone.** It only copies one level; nested objects and arrays remain shared references between the original and the copy.
- **Confusing rest parameters with spread at a glance.** `function f(...args)` collects arguments into an array; `f(...args)` expands an array into individual arguments - the direction depends entirely on context.
- **Forgetting that array destructuring needs an iterable.** It works on arrays, strings, and other iterables, but not on plain objects.

## Key points

- Object destructuring reads properties from an object by name and assigns them to bindings, with optional renaming and defaults.
- Array destructuring consumes values from an iterable by position, and can skip positions or collect the rest.
- Spread expands iterable items or object properties into a new context; rest collects remaining arguments, elements, or properties into one value.
- Object spread creates a new top-level object but copies nested objects and arrays by reference, so they remain shared between the original and the copy.
