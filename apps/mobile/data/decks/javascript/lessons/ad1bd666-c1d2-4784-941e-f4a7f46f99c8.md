# Functions

Functions in JavaScript are not just reusable blocks of code - they are values you can store, pass around, and hand back out of other functions, and they carry their own rules for what `this` means inside them. Understanding functions as values explains closures and callback-based APIs; understanding `this` explains a huge share of confusing bugs in object-oriented and event-driven code. This lesson covers both.

## Functions are values

A **first-class function** is a function that can be treated exactly like any other value: stored in a variable, passed as an argument, returned from another function, or placed inside an array or object. JavaScript functions are first-class:

```js
const double = function (x) {
  return x * 2;
};
const operations = [double, (x) => x + 1];
console.log(operations[0](5)); // 10
```

Being first-class is what makes the rest of this lesson possible - you cannot pass a function to another function, or have a function build and return another function, unless functions are values in the first place.

## Higher-order functions

A **higher-order function** is a function that takes one or more functions as arguments, returns a function, or both. `Array.prototype.map` is higher-order because it takes a callback; a function that builds and returns a customized validator is higher-order because it returns a function.

```js
function multiplyBy(factor) {
  return function (x) {
    return x * factor;
  };
}
const triple = multiplyBy(3);
console.log(triple(7)); // 21
```

## Closures

`multiplyBy` above only works because of **closures**. A closure is a function together with access to the lexical bindings that existed where it was created - even after the outer function has finished running. `triple` keeps working long after `multiplyBy(3)` has returned, because it still has access to `factor`.

```js
function makeCounter() {
  let count = 0;
  return () => ++count;
}

const next = makeCounter();
console.log(next(), next(), next()); // 1 2 3
```

`makeCounter` runs and returns, yet the returned function still reads and updates `count`. That variable is effectively private - nothing outside the closure can reach it directly.

Closures are useful whenever a function needs to **remember state or context** without resorting to global variables: counters and caches (as above), functions preconfigured with settings, and event handlers or callbacks that need to recall values from when they were registered.

## How this is determined for a normal function

Unlike a variable captured by a closure, `this` inside an ordinary `function` is **not** determined by where the function is written. It's determined by _how the function is called_:

- **Method call** (`obj.method()`) - `this` is `obj`.
- **Constructor call** (`new Fn()`) - `this` is the newly created object.
- **Explicit binding** (`fn.call(x)`, `fn.apply(x)`, `fn.bind(x)`) - `this` is whatever was supplied.
- **Plain call** (`fn()`) - `this` is `undefined` in strict-mode code (or the global object in non-strict, non-module code).

```js
function whoAmI() {
  return this;
}
const obj = { whoAmI };
console.log(obj.whoAmI() === obj); // true: called as a method
console.log(whoAmI.call("x")); // "x": explicit call
```

## Arrow functions and this

**Arrow functions do not create their own `this`.** Instead, they capture `this` lexically from whatever scope surrounds them when they're defined - the same way a closure captures an ordinary variable. Regular functions, by contrast, get `this` from the call form above, regardless of where they're written.

```js
const obj = {
  name: "Ada",
  regularGreet() {
    console.log("regular:", this.name); // "regular: Ada" - called as obj.regularGreet()
  },
  arrowGreet: () => {
    console.log("arrow:", this?.name); // undefined - this comes from the outer scope, not obj
  },
};
obj.regularGreet();
obj.arrowGreet();
```

This is exactly why arrow functions are the natural choice for callbacks that need to reuse the surrounding `this` (for example, inside a class method), while a plain method that will be called as `obj.method()` should stay a regular function.

## Why arrow functions can't be constructors

Because arrow functions have no notion of their own `this`, they also have no constructor behavior and no own `prototype` property to attach to instances. Calling one with `new` throws:

```js
const Arrow = (x) => {
  this.x = x;
};
new Arrow(1); // TypeError: Arrow is not a constructor
```

## Fixing this with bind, call, and apply

Three built-in methods let you control `this` explicitly instead of relying on call form:

**`Function.prototype.bind`** creates a **new function** with `this` (and optionally some leading arguments) permanently fixed; calling the bound function later cannot change that `this`.

```js
function greet(greeting, name) {
  console.log(`${greeting}, ${name}`);
}
const greetAda = greet.bind(null, "Hello", "Ada");
greetAda(); // "Hello, Ada" - this and both arguments are fixed
```

**`call`** and **`apply`** both invoke a function _immediately_ with an explicit `this`, but differ in how they pass the remaining arguments: `call` takes them individually, `apply` takes them as a single array-like value.

```js
greet.call(null, "Hi", "Bob"); // "Hi, Bob"
greet.apply(null, ["Hey", "Cy"]); // "Hey, Cy"
```

## Common mistakes

- **Using an arrow function for an object method that needs `this` to be the object.** It will silently capture `this` from the enclosing scope instead, which is rarely the receiver you want.
- **Passing a method as a bare callback and losing its `this`.** `setTimeout(obj.method, 100)` calls `method` as a plain function, so `this` inside it is `undefined`, not `obj`. Use `obj.method.bind(obj)` or an arrow wrapper.
- **Confusing `call`'s and `apply`'s argument style.** `fn.call(ctx, a, b)` vs. `fn.apply(ctx, [a, b])` - mixing them up passes an array where an individual argument was expected.

## Key points

- A first-class function can be stored, passed, returned, and placed in data structures like any other value.
- A higher-order function takes one or more functions as arguments, returns a function, or both.
- A closure is a function plus access to the lexical bindings from where it was created, even after the outer function returns; this lets functions retain private state such as counters or configuration without globals.
- For an ordinary function, `this` depends on the call form: method call, constructor call, explicit `call`/`apply`/`bind`, or plain call.
- Arrow functions capture `this` lexically from the surrounding scope instead of from how they're called, and so cannot be used as constructors.
- `bind` returns a new function with a fixed `this` (and optional leading arguments); `call` and `apply` invoke immediately with an explicit `this`, differing only in how the remaining arguments are passed.
