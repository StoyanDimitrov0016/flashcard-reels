# Array methods

Transforming a list - doubling every number, keeping only the matches, combining everything into a total - is one of the most common things code does, and JavaScript's array methods let you express each of those operations as a single expression instead of a hand-written loop. This lesson covers the core transformation methods, the two ways to carve up an array, and a hazard that appears when you mutate an array while iterating it.

## map

**`Array.prototype.map`** returns a **new array** containing the callback's result for each source element, preserving the source's length and order.

```js
const prices = [10, 20, 30];
const withTax = prices.map((price) => price * 1.2);
console.log(withTax); // [12, 24, 36]
console.log(prices); // [10, 20, 30] - unchanged
```

## filter

**`Array.prototype.filter`** returns a **new array** containing only the elements for which the callback returned a truthy result. The result can be shorter than the source; it's never longer.

```js
const numbers = [1, 2, 3, 4, 5];
const evens = numbers.filter((n) => n % 2 === 0);
console.log(evens); // [2, 4]
```

## reduce

**`Array.prototype.reduce`** processes elements **in order**, carrying an **accumulator** from one callback call to the next, and returns the final accumulator value. It's the most general of the three: `map` and `filter` can both be written in terms of `reduce`, though the dedicated methods are usually clearer.

```js
const total = [10, 20, 30].reduce((acc, n) => acc + n, 0);
console.log(total); // 60

const grouped = ["a", "bb", "ccc"].reduce((acc, word) => {
  (acc[word.length] ??= []).push(word);
  return acc;
}, {});
console.log(grouped); // { '1': ['a'], '2': ['bb'], '3': ['ccc'] }
```

## slice vs. splice

These two names are easy to mix up, and they behave very differently. **`slice(start, end)`** returns a **shallow copy** of a range and never touches the original array. **`splice(start, deleteCount, ...items)`** **mutates the original array in place**, removing, replacing, or inserting elements, and returns the removed elements.

```js
const letters = ["a", "b", "c", "d"];
const copy = letters.slice(1, 3);
console.log(copy, letters); // ['b', 'c']  ['a', 'b', 'c', 'd'] - source untouched

const removed = letters.splice(1, 2, "X");
console.log(removed, letters); // ['b', 'c']  ['a', 'X', 'd'] - source mutated
```

## Mutating an array during iteration

Changing an array's length or index positions while a loop or iteration method is still working through it can cause elements to be **skipped, revisited, or read mid-shift**, because the array's indices moved out from under the iteration:

```js
const items = ["a", "b", "c"];
items.forEach((item, i) => {
  console.log(i, item);
  if (item === "a") items.splice(1, 1); // removes "b" while forEach is mid-loop
});
// logs: 0 'a'  then  1 'c'  -- "b" is never visited; splice shifted "c" into its slot
```

`forEach` (like most iteration methods) re-reads the array's current length and contents on each step; once `splice` shifted `"c"` into index `1`, the loop's next step landed on `"c"`, and `"b"` was skipped entirely. The exact symptom depends on the method - `map`/`filter` have their own subtleties too - but the safe rule is the same: don't mutate the array you're currently iterating. Iterate over a copy (`for (const x of [...items])`) or collect indices to remove and apply the change after the loop finishes.

## Array.from

**`Array.from`** builds a **real array** from an iterable or an **array-like** value (something with a numeric `length` and indexed properties, but no array methods), and can optionally apply a mapping function to each item as it builds the array:

```js
Array.from("abc"); // ['a', 'b', 'c'] - a string is iterable
Array.from({ length: 3 }, (_, i) => i * 2); // [0, 2, 4] - array-like + mapper
Array.from(new Set([1, 2, 2, 3])); // [1, 2, 3] - dedupes via Set, then arrays
```

This is the standard way to turn `arguments`, a `NodeList`, or a `Set`/`Map` into a real array that supports `map`, `filter`, and `reduce`.

## Common mistakes

- **Confusing `slice` and `splice`.** `slice` is read-only and returns a copy; `splice` mutates the source. Reaching for the wrong one either mutates data you meant to keep, or fails to update data you meant to change.
- **Mutating an array inside `forEach`/`map`/`filter` while it's still iterating.** This can skip or double-process elements; iterate a copy or collect changes and apply them afterward.
- **Forgetting `reduce` needs an initial value for an empty array.** Without one, calling `reduce` on `[]` throws; passing an explicit initial value avoids that case entirely.

## Key points

- `map` returns a new array of callback results, same length and order as the source.
- `filter` returns a new array containing only elements where the callback was truthy.
- `reduce` carries an accumulator across the array in order and returns the final value.
- `slice` returns a shallow copy of a range without changing the source; `splice` mutates the source by removing, replacing, or inserting elements.
- Mutating an array's length or indices during iteration can cause elements to be skipped, revisited, or observed inconsistently.
- `Array.from` creates a real array from an iterable or array-like value, optionally mapping each item during creation.
