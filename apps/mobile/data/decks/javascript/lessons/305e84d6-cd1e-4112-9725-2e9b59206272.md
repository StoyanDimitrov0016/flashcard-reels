# The prototype chain

Every object in JavaScript can "inherit" behavior from another object, and this is true whether you write plain object literals, `Object.create`, constructor functions, or `class` syntax - they're all different ways of wiring up the same underlying mechanism. Understanding that mechanism explains where methods like `.toString()` come from, why `instanceof` works the way it does, and why classes in JavaScript are not a separate feature bolted on top of objects.

## The prototype chain

Every object has an internal link to another object (or to `null`): its **prototype**. When you read a property that isn't found directly on an object, JavaScript doesn't give up - it follows that internal link to the object's prototype, checks there, and keeps following prototype links until it finds the property or reaches an object whose prototype is `null`. This sequence of linked objects is the **prototype chain**.

```js
const animal = {
  speak() {
    return "...";
  },
};
const dog = Object.create(animal);
console.log(dog.speak()); // "...": not on dog, found on its prototype
```

## Object.create

**`Object.create(proto)`** builds this link directly: it creates a brand-new object whose prototype is exactly `proto`, with no constructor function involved at all.

```js
const dog = Object.create(animal);
dog.speak = function () {
  return "Woof";
};
console.log(dog.speak()); // "Woof": found directly on dog
console.log(Object.getPrototypeOf(dog) === animal); // true
```

## Property shadowing

Notice that `dog.speak` above stopped using `animal.speak` once `dog` got its own `speak` property. This is **property shadowing**: when an object has its own property with the same key as one further up its prototype chain, lookup finds the own property first and never reaches the prototype's version. The prototype's property still exists - it's just hidden behind the closer one for that particular object.

## The new operator

Most real code doesn't call `Object.create` directly. Instead, a **constructor function** paired with `new` does three things in one step: it creates a new object linked to the constructor's `prototype` property, calls the constructor with that new object as `this`, and returns the constructed object (unless the constructor explicitly returns some other object).

```js
function Point(x, y) {
  this.x = x;
  this.y = y;
}
Point.prototype.distanceFromOrigin = function () {
  return Math.sqrt(this.x ** 2 + this.y ** 2);
};

const p = new Point(3, 4);
console.log(p.distanceFromOrigin()); // 5
console.log(Object.getPrototypeOf(p) === Point.prototype); // true
```

Every `Point` instance shares the _same_ `distanceFromOrigin` function through the prototype, rather than each instance carrying its own copy - that sharing is the whole point of putting methods on the prototype instead of assigning them inside the constructor.

## Classes are prototypes with different syntax

JavaScript **classes are syntax over this exact prototype-based system** - `class` does not introduce a separate object model. A class's instance methods are stored on the class's `prototype` object, exactly like `Point.prototype.distanceFromOrigin` above, and are shared by every instance the same way.

```js
class Animal {
  speak() {
    return "...";
  }
}
class Dog extends Animal {
  speak() {
    return "Woof";
  }
}
console.log(Object.getPrototypeOf(Dog.prototype) === Animal.prototype); // true
console.log(typeof Animal.prototype.speak); // "function"
```

`extends` links `Dog.prototype`'s prototype to `Animal.prototype`, forming the same kind of chain `Object.create` builds by hand - `class` just gives that pattern clearer, less error-prone syntax.

## instanceof

**`instanceof`** tests this chain directly: `obj instanceof Ctor` checks whether `Ctor.prototype` appears anywhere in `obj`'s prototype chain.

```js
const d = new Dog();
console.log(d instanceof Dog); // true: Dog.prototype is d's direct prototype
console.log(d instanceof Animal); // true: Animal.prototype is further up the chain
```

## Why instanceof can be unreliable across realms

`instanceof` compares against one specific `prototype` object - and different **realms** (separate browser frames, windows, or workers) each have their own built-in constructors and prototypes, even for the "same" type. An array created in one iframe has `Array.prototype` from _that_ iframe as its prototype, not the `Array.prototype` of the page that received it. So `instanceof Array` can report `false` for a genuine array that simply came from another realm, because the two realms' `Array.prototype` objects are different objects entirely.

## Common mistakes

- **Assuming shadowing deletes the prototype's property.** It doesn't; it only hides it for that one object. `delete`ing the own property reveals the prototype's version again.
- **Defining methods inside the constructor instead of on the prototype.** `this.method = function () {}` inside a constructor creates a new function per instance, losing the sharing (and memory savings) that prototype methods provide.
- **Trusting `instanceof` for values that might cross realm boundaries**, such as values from an iframe or a separate worker context; prefer duck-typing or platform APIs designed for that case.

## Key points

- When a property isn't found directly on an object, JavaScript follows its prototype chain until it finds the property or reaches `null`.
- `Object.create(proto)` creates a new object whose prototype is `proto` directly, without a constructor.
- Property shadowing happens when an object's own property has the same key as one on its prototype; lookup returns the own property first.
- `new` creates an object linked to the constructor's `prototype`, calls the constructor with that object as `this`, and returns it unless the constructor returns another object explicitly.
- Classes are syntax over prototypes: instance methods live on the class's `prototype` and are shared across instances.
- `instanceof` checks whether a constructor's `prototype` appears in an object's prototype chain, which can fail across realms that have their own separate built-in prototypes.
