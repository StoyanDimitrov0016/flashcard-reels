# Promises

Callback-based asynchronous code tends to nest deeply and makes error handling inconsistent - one callback might call its error argument, another might throw, another might silently swallow a failure. Promises give asynchronous results a single, predictable shape: something will eventually succeed or fail, exactly once, and that outcome can be chained through `.then()` no matter how many asynchronous steps are involved.

## What a Promise is

A **Promise** is an object representing the **eventual result** of an asynchronous operation - a network request, a timer, a file read. Rather than handing you a value immediately, it hands you something you can attach reactions to, and those reactions run once the underlying operation finishes.

```js
const request = new Promise((resolve, reject) => {
  setTimeout(() => resolve(42), 10);
});
request.then((value) => console.log("fulfilled with", value)); // "fulfilled with 42" (after 10ms)
```

## Promise states

A Promise starts **pending** and can **settle exactly once**, either as **fulfilled** (with a value) or **rejected** (with a reason). Once settled, its state and result never change again - a later attempt to resolve or reject an already-settled Promise has no effect.

```js
const settled = Promise.resolve(1); // already fulfilled with 1
setTimeout(() => {
  settled.then((value) => console.log("still", value)); // "still 1" - unchanged later
}, 20);
```

This "settle once" guarantee is what makes Promises safe to hand to multiple consumers or attach handlers to at different times: everyone who asks gets the same final answer.

## What .then() returns

**`.then()`** always returns a **new Promise**, and that new Promise's outcome depends entirely on what the callback does:

- A **returned value** fulfills the new Promise with that value.
- A **thrown error** rejects the new Promise with that error.
- A **returned Promise** is adopted - the new Promise follows whatever that inner Promise eventually does.

```js
Promise.resolve(1)
  .then((value) => value + 1) // returns 2 -> fulfills the next Promise with 2
  .then((value) => console.log("chained:", value)); // "chained: 2"
```

This is what makes `.then()` chainable: each call produces a fresh Promise you can keep attaching more `.then()`s to, and each step can transform the value flowing through.

## What happens when a handler throws

Because a thrown error rejects the Promise `.then()` returns, an error raised inside any handler in a chain **propagates forward** as a rejection, skipping subsequent `.then()` callbacks until a `.catch()` (or a second `.then()` argument) handles it:

```js
Promise.resolve(1)
  .then(() => {
    throw new Error("bad");
  })
  .then(() => console.log("never runs")) // skipped: the chain is now rejected
  .catch((error) => console.log("caught:", error.message)); // "caught: bad"
```

This gives asynchronous code the same "error skips ahead until something catches it" behavior that `try`/`catch` gives synchronous code, even though the actual work happens across multiple turns of the event loop.

## Common mistakes

- **Forgetting that `.then()` returns a new Promise, not the same one.** Chained calls transform the value at each step; mutating a variable inside a `.then()` callback doesn't retroactively change what's already been passed downstream.
- **Assuming a rejected Promise "goes away" if nothing appears to happen.** Without a `.catch()` somewhere in the chain, the rejection is still there - it typically surfaces as an unhandled rejection warning or crash, not silence.
- **Expecting `resolve`/`reject` called a second time to change an already-settled Promise.** Only the first call has any effect; later calls are ignored.

## Key points

- A Promise represents the eventual result of an asynchronous operation, settling once as fulfilled with a value or rejected with a reason.
- A Promise begins pending and settles exactly once; after settlement, its state and result never change.
- `.then()` returns a new Promise whose outcome depends on the callback: returned values fulfill it, thrown errors reject it, returned Promises are adopted.
- A thrown error inside a Promise handler rejects the Promise that `.then()`/`.catch()` returns, letting the error propagate down the chain until something catches it.
