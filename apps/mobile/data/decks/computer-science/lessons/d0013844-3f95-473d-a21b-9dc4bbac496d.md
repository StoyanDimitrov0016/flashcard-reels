# Shortest paths

Once edges carry weights, "shortest path" stops meaning "fewest edges" (which breadth-first search already answers) and starts meaning "least total cost" — the cheapest route, not the one with the fewest stops. Finding it efficiently, especially from one starting point to everywhere else, is one of the most useful and most studied problems in graph algorithms.

## Dijkstra's algorithm

**Dijkstra's algorithm** finds shortest paths from one source in a graph with non-negative edge weights. It keeps a tentative distance for every vertex (initially infinite, except zero for the source), and repeatedly picks the unvisited vertex with the smallest tentative distance, marks it finalized, and **relaxes** its outgoing edges — updating a neighbor's tentative distance if reaching it through the current vertex would be cheaper than what is currently recorded.

```text
graph (undirected, weighted):
    A --4-- B
    |       |
    1       1
    |       |
    C --2-- D

Dijkstra from A:
  dist: A=0, B=inf, C=inf, D=inf
  finalize A (smallest, 0). Relax: B=4, C=1.
  finalize C (smallest unvisited, 1). Relax via C: D = 1+2 = 3.
  finalize D (smallest unvisited, 3). Relax via D: B = min(4, 3+1) = 4 (no change).
  finalize B (4).
final distances: A=0, C=1, D=3, B=4
```

The vertex with the smallest tentative distance is always finalized correctly, _because_ every edge weight is non-negative: nothing not yet reached could possibly offer a cheaper route to it than what has already been finalized. That single fact is also exactly why the algorithm breaks with negative weights.

## Why negative weights break Dijkstra

Dijkstra's algorithm assumes that once the smallest tentative distance is finalized, no later path can improve it — a negative edge can violate that assumption, because a longer path through a very negative edge could still end up cheaper than a shorter path already marked "done." Concretely:

```text
directed edges: A -> B (2), A -> C (5), C -> B (-4)

Dijkstra from A:
  finalize A (0). Relax: B=2, C=5.
  finalize B (smallest unvisited, 2).
  finalize C (5). Relax via C: B would be 5 + (-4) = 1, but B is already final.
result: B=2, although the path A -> C -> B costs 1
```

Dijkstra never reconsiders `B` once it is finalized, so it produces a wrong answer instead of an error. The algorithm has no built-in way to detect that its own core assumption has failed; it simply computes the wrong number silently.

## Bellman-Ford

**Bellman-Ford** finds single-source shortest paths even with negative edge weights, and can detect a reachable negative-weight cycle. Instead of greedily finalizing one vertex at a time, it relaxes _every_ edge in the graph, repeatedly, for `V - 1` rounds (where `V` is the number of vertices) — enough rounds for the true shortest path to any vertex, which uses at most `V - 1` edges, to have been fully propagated regardless of which order edges happen to be processed in.

After `V - 1` rounds, a correct shortest-path graph has stopped changing. Bellman-Ford runs one more round anyway: if any distance still improves, that can only happen because a **negative-weight cycle** is reachable — a cycle whose total edge weight is negative, which means walking around it repeatedly makes the "shortest path" arbitrarily small, so no finite shortest path even exists. That extra round is how the algorithm detects the problem rather than looping forever or returning a meaningless number. The cost of this generality is speed: Bellman-Ford is `O(V · E)`, slower than Dijkstra's `O((V + E) log V)` with a binary-heap priority queue, so Dijkstra remains the better default whenever weights are known to be non-negative.

## Floyd-Warshall

Both Dijkstra and Bellman-Ford answer "shortest paths from _one_ source." **Floyd-Warshall** computes shortest-path distances between _all pairs_ of vertices, using dynamic programming, in `O(V³)` time. Its structure directly mirrors the dynamic-programming lesson's core idea: it considers, for each vertex `k` in turn, whether routing a path _through_ `k` shortens the currently known best distance between every pair `(i, j)`:

```text
for k in vertices:
    for i in vertices:
        for j in vertices:
            dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])
```

After considering all `k`, `dist[i][j]` holds the true shortest distance between every pair. `O(V³)` is worse than running Dijkstra from every vertex when the graph is sparse, but Floyd-Warshall's simplicity and its ability to handle negative edges (though not negative cycles, which it can also detect via a negative value on its own diagonal) make it a common choice when `V` is small and all-pairs distances are genuinely needed, rather than distances from a single source.

## Choosing among the three

- All edge weights non-negative, need distances from one source: **Dijkstra**.
- Some edge weights negative, need distances from one source (or need to detect a negative cycle): **Bellman-Ford**.
- Need distances between every pair of vertices, and the graph is small enough for `O(V³)`: **Floyd-Warshall**.

## Common mistakes

- **Running Dijkstra on a graph with negative edges and trusting the result.** It will not necessarily crash or warn — it can simply return an incorrect shortest distance.
- **Forgetting Bellman-Ford's extra round is what detects negative cycles.** Stopping after exactly `V - 1` rounds finds correct distances when no negative cycle exists, but gives no way to notice one when it does.
- **Choosing Floyd-Warshall by default for single-source problems.** Its `O(V³)` cost is wasted work when only one source's distances are needed.
- **Confusing "negative edge weight" with "negative-weight cycle."** A graph can have individual negative edges and still have well-defined shortest paths, as long as no cycle's total weight is negative.

## Key points

- Dijkstra's algorithm finds single-source shortest paths in graphs with non-negative edge weights by always finalizing the closest unvisited vertex.
- Dijkstra fails with negative edges because a finalized vertex's distance can no longer be improved even when a cheaper route through a negative edge exists.
- Bellman-Ford finds single-source shortest paths even with negative edges, by relaxing every edge for `V - 1` rounds, and its extra round detects a reachable negative-weight cycle.
- Floyd-Warshall computes all-pairs shortest paths via dynamic programming in `O(V³)`.
- The right algorithm depends on whether weights can be negative and whether one source or all pairs are needed.
