# Minimum spanning trees

Suppose you need to connect a set of offices with network cable, or a set of towns with roads, as cheaply as possible — every location must be reachable, but you do not need more than one route between any two of them. This is a different question from shortest paths: instead of "cheapest route between two specific points," it asks "cheapest way to connect everything at once."

## Minimum spanning trees

A **minimum spanning tree** (MST) connects all vertices of a weighted undirected graph with no cycles and minimum total edge weight. "Spanning" means every vertex is included; "tree" means the result is connected with no cycles — exactly `V - 1` edges for `V` vertices, since a cycle would mean an edge could be removed while keeping everything connected, and removing edges only helps minimize total weight.

```text
    A --4-- B
    |  \    |
    1   3   2
    |    \  |
    C --5-- D

One minimum spanning tree: A-C (1), A-D (3), B-D (2)   total weight 6
(A-B at 4 and C-D at 5 are left out — they would only add a cycle)
```

Two classic algorithms build an MST from opposite directions: Kruskal's works globally across all edges at once, and Prim's grows one connected region outward.

## Kruskal's algorithm

**Kruskal's algorithm** processes edges from lowest to highest weight, adding an edge when it connects two previously separate components — that is, when the edge's two endpoints are not already connected through edges already chosen. Sorting all edges by weight up front, and then greedily taking each edge that does not create a cycle, is enough to guarantee a minimum-weight result — a fact you can trust because MST construction has the kind of greedy-choice-is-safe structure discussed in the algorithm design strategies lesson.

Walking through the example graph, sorted by weight: `A-C (1)`, `B-D (2)`, `A-D (3)`, `A-B (4)`, `C-D (5)`.

```text
A-C (1): A and C are separate -> add.        components: {A,C}, {B}, {D}
B-D (2): B and D are separate -> add.        components: {A,C}, {B,D}
A-D (3): A's component and D's component
         are separate -> add.                components: {A,C,B,D}
A-B (4): A and B already connected -> skip (would create a cycle)
C-D (5): already connected -> skip
```

## Union-find

The step "are these two vertices already connected through edges chosen so far" is exactly what **union-find** answers efficiently. Union-find maintains disjoint sets with operations to find a set representative and merge two sets, useful for connectivity problems — Kruskal's algorithm is the textbook example: each vertex starts in its own set, and adding an edge merges (unions) the two endpoints' sets. Two vertices are already connected exactly when `find` returns the same representative for both.

A naive union-find can still be slow if sets are merged carelessly, because `find` may have to walk a long chain of parent pointers to reach the representative. **Path compression** fixes this: during `find` operations it rewrites parent links toward the set root, making future finds much faster, because every node visited along the way is repointed directly at the root instead of at its immediate (possibly distant) parent.

```text
before find(x):   x -> p -> q -> root
after find(x):    x -> root, p -> root, q -> root   (all repointed directly)
```

Combined with union by rank or size (always attaching the smaller tree under the larger tree's root during a union, rather than the other way around), path compression makes union-find operations run in almost-constant amortized time in practice — far faster than the naive chain-walking approach, and easily fast enough that union-find's cost is not the bottleneck in Kruskal's algorithm; sorting the edges is.

## Prim's algorithm

**Prim's algorithm** grows one connected tree by repeatedly adding the cheapest edge from the current tree to a new vertex — rather than considering all edges globally like Kruskal's, it always looks only at edges leaving the tree built so far.

```text
start at A. tree = {A}
cheapest edge leaving {A}: A-C (1) -> add C.    tree = {A, C}
cheapest edge leaving {A,C}: A-D (3) [A-B is 4, C-D is 5] -> add D.  tree = {A, C, D}
cheapest edge leaving {A,C,D}: D-B (2) [A-B is 4] -> add B.  tree = {A, C, D, B}
```

Prim's arrives at the same total weight, 6, though it can pick a different set of edges depending on tie-breaking and starting vertex; both algorithms are guaranteed to find _a_ minimum, and when edge weights are all distinct, that minimum is unique. Prim's is usually implemented with a priority queue (the heap from two lessons back) to efficiently find "the cheapest edge leaving the current tree" at each step, which is why it tends to be preferred on dense graphs, while Kruskal's, dominated by the cost of sorting edges, tends to be preferred on sparse ones.

## Common mistakes

- **Adding an edge in Kruskal's algorithm without checking for a cycle.** Skipping the union-find check can connect two vertices that were already connected, producing a cycle and too few total edges to span the graph correctly.
- **Using a plain "walk to the root" union-find without path compression.** It still gives correct results but can be far slower on large graphs with many union operations.
- **Assuming Prim's and Kruskal's always pick the same edges.** They are both correct — guaranteeing the same minimum _total_ weight — but can select different edge sets when weights are not unique.
- **Applying MST algorithms to a directed graph.** Minimum spanning trees are defined over undirected graphs; the directed analogue (minimum arborescence) requires a different algorithm.

## Key points

- A minimum spanning tree connects all vertices of a weighted undirected graph with no cycles and minimum total edge weight.
- Kruskal's algorithm sorts edges by weight and greedily adds each edge that connects two previously separate components.
- Union-find maintains disjoint sets and answers "are these already connected" efficiently, which is exactly what Kruskal's needs.
- Path compression rewrites parent links toward the root during `find`, making future find operations much faster.
- Prim's algorithm grows a single tree outward, always adding the cheapest edge leaving the tree built so far.
- Both algorithms find a correct minimum spanning tree; they differ in how they search and which graph densities they suit best.
