# Shortest paths and spanning trees

Once edges carry weights, new questions appear. What is the cheapest route from here to there? What is the cheapest way to connect everything? This lesson covers the classic algorithms for both, plus a small data structure that makes one of them fast.

## Dijkstra's algorithm

**Dijkstra's algorithm** finds the **shortest paths from one source** vertex to every other vertex in a graph with **non-negative edge weights**.

It keeps a tentative distance for each vertex, starting at zero for the source and infinity for everything else. On each step it picks the unfinished vertex with the **smallest tentative distance**, usually with a priority queue, **finalizes** it, and relaxes its outgoing edges: if going through this vertex gives a neighbor a shorter distance, that neighbor's tentative distance is updated.

The whole method rests on one assumption: once the smallest tentative distance is finalized, **no later path can improve it**. With non-negative weights that holds, because any other route must pass through vertices that are already at least as far away, and adding more edges can only make it longer.

## Why negative edges break Dijkstra

A **negative edge** violates that assumption. Suppose the source S has an edge to A of weight 2 and an edge to B of weight 5, and B has an edge to A of weight −4. Dijkstra finalizes A at distance 2 first. Later it discovers the path S → B → A with total weight 1, but A is already final, so the better answer is missed.

## Bellman-Ford

**Bellman-Ford** also solves **single-source shortest paths**, and it works **even with negative edge weights**. Instead of finalizing vertices greedily, it relaxes **every** edge, over and over, `V − 1` times. Since a shortest path without cycles uses at most `V − 1` edges, that is enough for correct distances to propagate. The cost is higher: `O(V · E)`.

It has one more ability. If one extra round still improves some distance, the graph contains a **negative-weight cycle** reachable from the source. Going around such a cycle lowers the cost without limit, so no shortest path exists, and Bellman-Ford can **detect** that.

## Floyd-Warshall

Sometimes you need the distance between **every pair** of vertices. **Floyd-Warshall** computes all-pairs shortest-path distances with **dynamic programming** in **O(V³)** time.

The idea is to allow intermediate vertices one at a time. After considering vertex `k`, the table holds the best distance between every pair using only the first `k` vertices as stopovers:

```js
for (let k = 0; k < n; k++)
  for (let i = 0; i < n; i++)
    for (let j = 0; j < n; j++) dist[i][j] = Math.min(dist[i][j], dist[i][k] + dist[k][j]);
```

It is simple and works well for small, dense graphs.

## Minimum spanning trees

A different question: given a **weighted undirected** graph, how do you connect **all vertices** as cheaply as possible? A **minimum spanning tree (MST)** is a set of edges that connects every vertex, contains **no cycles**, and has the **minimum total edge weight**. Laying cable between buildings or designing a road network with the least material are MST problems. Two greedy algorithms find one.

**Kruskal's algorithm** looks at edges globally. It processes them from **lowest to highest weight** and adds an edge only if it **connects two previously separate components**. An edge whose endpoints are already connected would form a cycle, so it is skipped.

**Prim's algorithm** grows **one connected tree** from a starting vertex. At each step it adds the **cheapest edge from the current tree to a new vertex** not yet in it, much like Dijkstra, except it compares single edge weights rather than total path lengths.

## Union-find

Kruskal needs to ask, quickly and repeatedly, "are these two vertices already in the same component?" **Union-find**, also called a disjoint-set structure, answers exactly that. It maintains a collection of **disjoint sets** with two operations:

- `find(x)` returns the **representative** (root) of the set containing `x`. Two items are in the same set when their representatives match.
- `union(x, y)` **merges** the two sets containing `x` and `y`.

Each set is stored as a tree of parent links, with the representative at the root. Beyond Kruskal, it is useful for many **connectivity problems**, such as tracking which computers in a network can reach each other as links are added.

**Path compression** keeps those trees shallow. During a `find`, every node visited on the way up is re-pointed directly at the root, so **future finds are much faster**:

```js
function find(parent, x) {
  if (parent[x] !== x) {
    parent[x] = find(parent, parent[x]); // point straight at the root
  }
  return parent[x];
}
```

Combined with union by rank or size, path compression makes each operation run in nearly constant amortized time.
