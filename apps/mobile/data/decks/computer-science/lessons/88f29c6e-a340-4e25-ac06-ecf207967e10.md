# Linear data structures

Every program has to store a collection of values somewhere and decide how to access them again. The right choice depends entirely on which operations matter: do you need to jump straight to the 10,000th element, or only ever add and remove from one end? This lesson covers the structures that store elements one after another — arrays and linked lists — and the three abstract access patterns built on top of them: stacks, queues, and deques. Trees, graphs, and hash tables, which organize data by relationship or by key instead of by position, come in later lessons.

## Data structures in general

A **data structure** organizes values and the relationships between them so that selected operations can be performed with useful time and space costs. That definition is deliberately open-ended: no structure is good at everything, and choosing one means choosing which operations you want to be fast, usually at the expense of others. The rest of this lesson, and the ones that follow it, are really a catalog of those trade-offs.

## Arrays

An **array** stores elements in indexed order, typically allowing `O(1)` access by index, because the address of element `i` can be computed directly from the array's start address and `i`, with no searching involved. The cost of that convenience shows up on insertion or deletion in the middle: making room for a new element, or closing the gap left by a removed one, may require shifting every element after it — `O(n)` in the worst case.

## Amortized analysis and dynamic arrays

A fixed-size array cannot grow past its original capacity. A **dynamic array** (Python's `list`, Java's `ArrayList`, C++'s `std::vector`) solves this by allocating a larger backing array and copying elements over whenever it runs out of room — usually doubling the capacity each time, rather than growing by a fixed amount.

That resize is expensive: copying `n` elements is `O(n)`. So why is appending to a dynamic array usually described as `O(1)`? The answer requires a different kind of analysis than looking at a single worst-case operation. **Amortized analysis** spreads the cost of occasional expensive operations across a sequence of operations, to bound the average cost per operation over that sequence — not the cost of any one operation in isolation.

Here is why dynamic-array append is amortized `O(1)`: most appends simply write into existing spare capacity, costing `O(1)`. Resizes are rare, but when one happens it copies many elements. Geometric growth (doubling) is what makes the arithmetic work out: after a resize to capacity `c`, roughly `c/2` cheap appends happen before the next resize is needed, so the total copying work across many appends stays proportional to the number of appends, not to its square.

```text
capacity:  1    2    4     8       16
appends:   1  | 1  | 2   | 4     | 8      ...
copies:    -  | 1  | 2   | 4     | 8      (a resize copies the current contents)
```

Summing copies across `n` appends gives roughly `1 + 2 + 4 + ... + n`, which is `O(n)` total — so the _average_ cost per append, amortized over the whole sequence, is `O(n)/n = O(1)`, even though any single append might trigger an `O(n)` resize.

## Linked lists

A **linked list** stores elements in nodes connected by references instead of by position in memory. Each node holds a value and a pointer to the next node (and, in a doubly linked list, to the previous one too).

```text
[10] -> [23] -> [7] -> [45] -> null
```

Insertion near a known node can be `O(1)`: splice a new node in by rewriting a couple of pointers, no shifting required. But finding the nth element requires traversal, walking node by node from the head, because there is no way to compute a node's memory address from its position the way array indexing does — that traversal is `O(n)`. Linked lists and arrays are, in this sense, mirror images: one is fast to index and slow to insert in the middle, the other is the reverse.

## Stacks

A **stack** is a last-in, first-out (LIFO) structure supporting operations such as push (add) and pop (remove) at one end. Whatever was added most recently is the first thing removed — like a stack of plates. Stacks can be implemented on top of either an array or a linked list; both give `O(1)` push and pop at the appropriate end. The call stack from the recursion lesson is a real-world stack: the most recently called function is the first one to return.

## Queues

A **queue** is a first-in, first-out (FIFO) structure where items are added at one end and removed from the other — the first item added is the first one removed, like a line of people. Breadth-first search, covered in the graph traversal lesson, uses a queue to process vertices in the order they were discovered.

## Deques

A **deque** (double-ended queue) supports insertion and removal at both the front and the back. It generalizes both stack and queue behavior in a single structure: using only one end gives stack behavior, using both ends in FIFO order gives queue behavior, and some algorithms (like certain sliding-window techniques) genuinely need access at both ends at once.

## Common mistakes

- **Choosing an array when frequent middle insertions dominate**, or a linked list when frequent random access dominates — each structure is fast at one and slow at the other.
- **Treating amortized `O(1)` as a per-operation guarantee.** A single append can still cost `O(n)` when it happens to trigger a resize; the guarantee is about the average over a sequence, which matters for total running time but not for worst-case latency of one call.
- **Popping or dequeuing from the wrong end.** Stack and queue behavior differ only in which end removal happens at; mixing them up silently turns a LIFO algorithm into a FIFO one or vice versa.
- **Forgetting that linked-list traversal is `O(n)`**, then writing code that repeatedly indexes into a linked list as if it were an array, turning an intended `O(n)` algorithm into `O(n²)`.

## Key points

- A data structure organizes values and relationships to make selected operations fast, always at some cost to others.
- An array gives `O(1)` indexed access but `O(n)` insertion or deletion in the middle.
- Amortized analysis bounds the average cost per operation over a sequence, not any single operation's worst case.
- Dynamic-array append is amortized `O(1)` because geometric growth makes total resize copying proportional to the number of appends.
- A linked list gives `O(1)` insertion near a known node but `O(n)` access by position.
- A stack is LIFO, a queue is FIFO, and a deque supports both patterns by allowing insertion and removal at either end.
