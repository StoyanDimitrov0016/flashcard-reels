# Heaps

A hospital triage queue does not treat patients first-come-first-served: the most urgent case goes first, no matter when they arrived. Plenty of algorithmic problems need the same thing — always process the "most important" item next, where importance can change as new items arrive. A plain queue or sorted list can do this, but only clumsily. The heap is the structure built specifically for it.

## Priority queues

A **priority queue** removes items according to priority rather than insertion order, commonly implemented with a heap. Unlike a stack or queue, where the removal rule is fixed by arrival order, a priority queue's removal rule is "give me the best one right now," where "best" is defined by whatever ordering the problem needs — smallest number, earliest deadline, shortest distance.

You could implement a priority queue with an unsorted array (`O(1)` insert, but `O(n)` to find the best item to remove) or a sorted array (`O(n)` insert to maintain order, but `O(1)` to remove the best item). Neither is good at both operations. A **binary heap** gets both to `O(log n)`.

## Binary heaps

A **binary heap** is a nearly complete binary tree that maintains a heap-order property, enabling `O(1)` access to the minimum or maximum and `O(log n)` insertion and removal. "Nearly complete" means every level is fully filled except possibly the last, which fills left to right — a shape so regular that the whole tree can be stored in a plain array, with a node at index `i` having children at indices `2i + 1` and `2i + 2`, and no pointers needed at all.

```text
        1
      /   \
     3     5
    / \   /
   4   8 9
```

Array form: `[1, 3, 5, 4, 8, 9]` — index 0 is the root, its children are at indices 1 and 2, and so on.

## Min-heaps

A **min-heap** maintains every parent value as no greater than its children, so the minimum element is always at the root — a heap where every parent is `≤` both its children, recursively, all the way down. (A max-heap is the mirror image, with every parent `≥` its children and the maximum at the root.) Because the property is only enforced between a node and its immediate children, and only recursively, a heap is _not_ fully sorted — a heap does not tell you whether the second-smallest element is the left child or the right child of the root, only that both are `≥` the root.

## Maintaining the heap property

Two operations keep the heap-order property intact as elements come and go:

- **Insert**: add the new element at the next open leaf position (keeping the tree nearly complete), then repeatedly swap it with its parent while it is smaller than that parent — "bubble up." This takes at most the tree's height, `O(log n)`, comparisons and swaps.
- **Extract-min**: remove the root (the minimum), move the _last_ leaf into the root position to keep the tree nearly complete, then repeatedly swap it with its smaller child while it is larger than that child — "sift down." Also `O(log n)`.

```text
Insert 2 into [1, 3, 5, 4, 8, 9]:
  place at next leaf:  [1, 3, 5, 4, 8, 9, 2]
  2 < parent 5 (index 2)? yes -> swap:   [1, 3, 2, 4, 8, 9, 5]
  2 < parent 1 (index 0)? no  -> stop.
```

Because both insert and extract-min only ever walk one path from a leaf to the root or from the root to a leaf, neither operation needs to inspect most of the heap — that single-path movement is exactly what keeps both operations `O(log n)` instead of `O(n)`.

## Why this matters beyond the abstract structure

Priority queues backed by heaps show up throughout the rest of this deck: Dijkstra's algorithm (shortest paths lesson) repeatedly extracts the currently-closest unvisited vertex, and heapsort (sorting lesson) is exactly the "insert everything, then extract-min repeatedly" idea turned into a sorting algorithm. Any time an algorithm's next step is "process whichever pending item is currently best," a heap-backed priority queue is very likely the right tool.

## Common mistakes

- **Assuming a heap is a fully sorted structure.** Only the path from any node up to the root is guaranteed ordered; sibling subtrees are not comparable to each other.
- **Forgetting to restore the heap shape before sifting down.** Extract-min must move the _last_ element into the root first, or the "nearly complete" shape breaks and the array-as-tree encoding stops working.
- **Confusing min-heap and max-heap conventions** when combining code from different sources — one gives fast access to the smallest element, the other to the largest, and they are not interchangeable without inverting every comparison.
- **Using a heap when you need to search for an arbitrary element.** A heap is optimized for "give me the best item," not "does this specific value exist" — that lookup is `O(n)` in a heap, unlike a hash table or balanced search tree.

## Key points

- A priority queue removes items by priority rather than by arrival order, and is commonly implemented with a heap.
- A binary heap is a nearly complete binary tree stored compactly in an array, giving `O(1)` access to the best element and `O(log n)` insertion and removal.
- A min-heap keeps every parent `≤` its children, so the minimum is always at the root; a max-heap is the mirror image.
- Insert bubbles a new element up toward the root; extract-min moves the last element to the root and sifts it down — both take `O(log n)`.
- A heap is only partially ordered: it guarantees root-to-leaf ordering, not a full sort.
