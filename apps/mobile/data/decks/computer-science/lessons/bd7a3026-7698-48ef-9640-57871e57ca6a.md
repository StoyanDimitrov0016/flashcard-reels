# Algorithm design strategies

Dynamic programming is one general strategy for building algorithms; it is not the only one. This lesson surveys four more: greedy algorithms, which commit to locally best choices; divide and conquer, which splits a problem into independent pieces; backtracking, which explores candidates and abandons dead ends; and branch and bound, which prunes an exhaustive search using known bounds. Together with recursion and dynamic programming, these are the main tools algorithm designers reach for before inventing something bespoke.

## Greedy algorithms

A **greedy algorithm** repeatedly makes a locally best choice without revisiting previous choices. At each step, it picks whatever looks best right now — the cheapest edge, the earliest deadline, the largest remaining item — and never reconsiders that pick later. Kruskal's algorithm from the minimum spanning trees lesson is a greedy algorithm: it always takes the cheapest edge that does not create a cycle, and never undoes that decision.

Greedy is tempting because it is simple and fast, but it is not automatically correct. A greedy strategy is correct only when the problem has a property proving that locally optimal choices can be extended into a globally optimal solution — informally, that an early greedy commitment can never box you into a worse overall outcome than some other, less greedy sequence of choices would have reached. Kruskal's algorithm has this property (provable via an exchange argument showing any non-greedy MST can be transformed into the greedy one without increasing total weight); many superficially similar-looking problems do not, and greedy solutions to them are simply wrong, not just occasionally suboptimal.

```text
Coin change with denominations {1, 3, 4}, target 6:
  greedy: pick largest coin <= remaining each time
    6 -> pick 4, remaining 2 -> pick 1, remaining 1 -> pick 1, remaining 0
    result: 4 + 1 + 1 = 3 coins
  optimal: 3 + 3 = 2 coins
```

Greedy fails here because this particular coin set does not have the required property — taking the largest coin available is not always extendable into the true optimum. Dynamic programming solves general coin-change problems correctly, precisely because it considers subproblems rather than committing early.

## Divide and conquer

**Divide and conquer** splits a problem into smaller independent subproblems, solves them recursively, and combines their results. Merge sort (sorting lesson) is the canonical example: split the array in half, sort each half recursively, and merge the two sorted halves — each half's sort is entirely independent of the other's.

This is the key distinction from dynamic programming: divide and conquer's subproblems do not overlap. Splitting an array of 8 elements into two halves of 4 produces two genuinely disjoint slices of the array; there is nothing shared to cache. When subproblems do overlap, plain divide and conquer degenerates into exactly the exponential-blowup problem the dynamic programming lesson opened with — which is why naive recursive Fibonacci is sometimes described as "divide and conquer without noticing the overlap," rather than a real divide-and-conquer algorithm.

## Backtracking

**Backtracking** incrementally builds candidates and abandons a partial candidate as soon as it cannot lead to a valid solution. It is a systematic way to explore a search space that would be too large to enumerate in full, by cutting off entire branches the moment they are provably useless.

```text
placing queens on a chessboard, one column at a time:
  place queen in column 1 -> place queen in column 2
    -> conflicts with column 1's queen -> abandon, try next row in column 2
    -> no conflict -> place queen in column 3 ...
```

The moment a partial placement is known to conflict, backtracking stops extending it — it never finishes building an invalid candidate just to discover the problem at the end. This is what separates backtracking from brute-force enumeration: brute force generates every full candidate and checks it; backtracking checks validity as early as possible and prunes accordingly.

## Branch and bound

**Branch and bound** explores a search space while using bounds on the best possible remaining result to prune branches that cannot beat the current best solution. Like backtracking, it builds candidates incrementally and abandons unpromising branches early — but where backtracking prunes branches that are _invalid_, branch and bound also prunes branches that are merely _worse than what has already been found_, using a computed bound on the best score that branch could possibly still achieve.

For an optimization problem like the traveling salesperson problem, a partial route's bound might be its cost so far plus a cheap-to-compute underestimate of the remaining cost. If that bound already exceeds the best complete route found so far, the entire branch can be discarded without exploring it further — no matter how it might have continued, it cannot win.

## Choosing a strategy

- The problem needs the single best/cheapest choice at each step, and you can prove locally-optimal choices compose into a global optimum: **greedy**.
- The problem splits into genuinely independent pieces with no shared subproblems: **divide and conquer**.
- The problem splits into overlapping subproblems whose results are worth caching: **dynamic programming** (previous lesson).
- The problem requires finding _any_ valid arrangement among many candidates, most of which are invalid: **backtracking**.
- The problem requires finding the _best_ arrangement, and partial solutions can be scored to prune inferior branches: **branch and bound**.

## Common mistakes

- **Assuming a locally-optimal choice is safe without proving it.** Greedy algorithms need a specific correctness argument; "it seemed reasonable" is not one, as the coin-change example shows.
- **Applying divide and conquer to a problem with overlapping subproblems.** Without memoization, the recursion recomputes shared work repeatedly, and running time can blow up exponentially.
- **Confusing backtracking with brute force.** The point of backtracking is pruning invalid branches as early as possible, not generating and checking every full candidate.
- **Using backtracking's validity check as branch and bound's optimality bound.** Branch and bound needs an actual numeric bound on best-possible remaining value, not just a yes/no validity test.

## Key points

- A greedy algorithm makes locally best choices without revisiting them, and is only correct when the problem provably supports it.
- Divide and conquer splits a problem into independent subproblems, solves them recursively, and combines the results.
- Divide and conquer differs from dynamic programming in that its subproblems do not overlap.
- Backtracking builds candidates incrementally and abandons a partial candidate as soon as it cannot lead to a valid solution.
- Branch and bound extends backtracking's pruning with numeric bounds, discarding branches that cannot beat the best solution found so far.
