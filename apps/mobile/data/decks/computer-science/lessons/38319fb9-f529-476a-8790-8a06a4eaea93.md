# Sequence techniques

A surprising number of everyday problems on arrays and strings — "find a pair that sums to a target," "find the largest sum over any 5 consecutive elements," "answer many range-sum queries quickly" — have an obvious `O(n²)` solution (check every pair, recompute every range from scratch) and a much faster `O(n)` or `O(n log n)` solution that reuses work instead of redoing it. This lesson collects five small, reusable techniques that turn that obvious slow approach into a fast one.

## Two-pointer

A **two-pointer technique** maintains two indexes that move according to an invariant, often reducing nested scanning of ordered or sequence data to linear time. Instead of checking every pair of positions (`O(n²)`), it advances one or both pointers based on what has been learned so far, so each pointer only ever moves forward.

```text
sorted array: [1, 3, 5, 7, 9], target sum: 12
left=0 (1), right=4 (9): 1+9=10 < 12  -> move left forward
left=1 (3), right=4 (9): 3+9=12       -> found!
```

The invariant here is that the array is sorted: if the current sum is too small, moving `right` left could only make it smaller too, so `left` must move right instead; if too large, the reverse. That invariant is exactly what guarantees neither pointer ever needs to move backward, which is what keeps the whole scan `O(n)` instead of `O(n²)`.

## Sliding window

A **sliding window technique** maintains information about a contiguous range while moving its boundaries, reusing work instead of recomputing every range from scratch. Where two-pointer often looks for a single matching pair, a sliding window typically tracks an aggregate — a sum, a count, a set of seen characters — over a range that grows and shrinks as its edges move.

```text
array: [2, 1, 5, 1, 3, 2], window size 3, find max window sum
window [2,1,5] sum=8
slide: drop 2, add 1 -> [1,5,1] sum=8-2+1=7
slide: drop 1, add 3 -> [5,1,3] sum=7-1+3=9
slide: drop 5, add 2 -> [1,3,2] sum=9-5+2=6
max sum: 9
```

Each slide updates the running sum in `O(1)` by subtracting the element leaving the window and adding the one entering it, instead of re-summing the whole window — turning what looks like `O(n · k)` work (recomputing a sum over every window of size `k`) into `O(n)`.

## Prefix sums

A **prefix-sum array** stores cumulative totals so a range sum can be computed from two prefix values in `O(1)` after `O(n)` preprocessing.

```text
array:       [4, 2, 5, 1, 3]
prefix sums: [4, 6, 11, 12, 15]   (prefix[i] = sum of array[0..i])

sum of array[1..3] (indices 1 through 3, inclusive) = prefix[3] - prefix[0] = 12 - 4 = 8
check: 2 + 5 + 1 = 8  ✓
```

Once the prefix array is built (one linear pass), any range sum becomes a single subtraction, regardless of how long that range is — this is the same "pay once, reuse many times" idea as the sliding window's running total, generalized to arbitrary ranges rather than only a fixed-size window.

## Monotonic stacks

A **monotonic stack** keeps elements in increasing or decreasing order while processing a sequence, enabling nearest-greater or nearest-smaller queries in linear time. Instead of comparing each element against every other element to find its nearest larger neighbor (`O(n²)`), a monotonic stack processes elements once, popping off anything the current element makes obsolete.

```text
array: [2, 1, 4, 3], find next greater element for each

process 2: stack=[2]
process 1: 1 < 2, push.                stack=[2, 1]
process 4: 4 > 1 -> pop 1, next-greater[1]=4
           4 > 2 -> pop 2, next-greater[2]=4
           push 4.                     stack=[4]
process 3: 3 < 4, push.                stack=[4, 3]
end: 4 and 3 have no next greater element.
```

Each element is pushed once and popped at most once, so total work across the whole array is `O(n)` even though it looks like nested comparisons are happening — the stack only ever holds elements still waiting for their answer, which is what keeps the total number of comparisons linear.

## Bitsets

A **bitset** stores many Boolean flags compactly and lets word-sized bit operations process many flags at once. Instead of one byte (or more) per flag, a bitset packs 64 flags into a single 64-bit machine word, and operations like AND, OR, and XOR across two bitsets process all 64 flags in one CPU instruction rather than 64 separate ones.

```text
set A: bit i = 1 if i is in {1, 3, 5}   -> 0b101010
set B: bit i = 1 if i is in {3, 4, 5}   -> 0b111000
A AND B (intersection): 0b101010 & 0b111000 = 0b101000  -> {3, 5}
```

This makes bitsets a natural fit for problems like reachability over a small fixed universe, subset-sum style dynamic programming, or any place a plain `set` of small integers would work but memory and constant-factor speed both matter.

## Common mistakes

- **Using two-pointer on unsorted data without sorting first (when the technique requires order).** The invariant that lets a pointer only move forward depends on the data actually being ordered along the dimension being scanned.
- **Recomputing a sliding window's aggregate from scratch on every slide.** This silently turns an intended `O(n)` algorithm back into `O(n · k)`, defeating the technique's whole purpose.
- **Off-by-one errors in prefix-sum range queries.** Whether a range is `[l, r]` inclusive or exclusive changes whether the correct formula is `prefix[r] - prefix[l - 1]` or `prefix[r] - prefix[l]` — define the convention before writing the subtraction.
- **Assuming a monotonic stack solves problems needing global order, not just nearest-neighbor order.** It answers "nearest greater/smaller element" efficiently; it is not a substitute for a sorted structure when arbitrary ranking queries are needed.

## Key points

- Two-pointer maintains two indexes that move according to an invariant, often turning nested scans into a single linear pass.
- Sliding window maintains an aggregate over a moving contiguous range, updating in `O(1)` per slide instead of recomputing.
- A prefix-sum array precomputes cumulative totals so any range sum becomes an `O(1)` subtraction.
- A monotonic stack keeps elements ordered while scanning, answering nearest-greater or nearest-smaller queries in total `O(n)` time.
- A bitset packs many Boolean flags into machine words, letting bitwise operations process many flags per instruction.
