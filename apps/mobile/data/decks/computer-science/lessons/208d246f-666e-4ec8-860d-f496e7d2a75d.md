# Techniques and correctness

Beyond the big paradigms, a handful of small, reusable techniques solve a surprising number of everyday problems in linear time. This lesson collects those techniques, then turns to the tools used to reason about whether an algorithm is actually correct.

## Two pointers

The **two-pointer technique** keeps **two indexes** into a sequence and moves them according to an **invariant**. It often turns a nested scan, which is `O(n²)`, into a single **linear-time** pass over ordered or sequential data.

A classic example: find two numbers in a sorted array that add up to a target. Start one pointer at each end. If the sum is too small, move the left pointer right; if it is too large, move the right pointer left.

```js
function hasPairWithSum(sorted, target) {
  let left = 0;
  let right = sorted.length - 1;
  while (left < right) {
    const sum = sorted[left] + sorted[right];
    if (sum === target) return true;
    if (sum < target) left++;
    else right--;
  }
  return false;
}
```

## Sliding window

The **sliding window** technique maintains information about a **contiguous range** while moving its boundaries. Instead of recomputing every range from scratch, it **reuses work**: when the window slides one step, it adds the element entering and removes the element leaving.

To find the largest sum of any three consecutive values, compute the first window's sum once, then for each step add the new right element and subtract the old left one. Each step is `O(1)`, so the whole scan is `O(n)`.

## Prefix sums

A **prefix-sum** array stores **cumulative totals**: `prefix[i]` is the sum of the first `i` elements. Building it takes **O(n)** preprocessing. After that, the sum of any range is the difference of **two prefix values**, computed in **O(1)**.

```js
// prefix[i] = sum of values[0..i-1]
const values = [3, 1, 4, 1, 5];
const prefix = [0, 3, 4, 8, 9, 14];
// Sum of values[1..3] = prefix[4] - prefix[1] = 9 - 3 = 6
```

This is ideal when many range-sum queries are asked against data that does not change.

## Monotonic stacks

A **monotonic stack** keeps its elements in strictly **increasing or decreasing order** as a sequence is processed. Before pushing a new element, it pops every element that would break the order.

The popped elements have just found their answer. For "next greater element" queries, a value is popped exactly when a larger value arrives, and that larger value is its nearest greater element to the right. Because each element is pushed and popped at most once, **nearest-greater or nearest-smaller queries** for the whole sequence take **linear time**.

## Bitsets

A **bitset** stores many **Boolean flags compactly**, one bit each, packed into machine words. A 64-bit word holds 64 flags. Beyond saving memory, **word-sized bit operations** like AND, OR, and XOR process all of a word's flags **at once**. Intersecting two sets of permissions or marking which of a thousand items have been seen becomes a handful of fast instructions.

## The pigeonhole principle

The **pigeonhole principle** says that if you place **more items than containers**, at least one container must hold **more than one item**. Put 13 people in a room and at least two share a birth month.

It sounds obvious, but it is a powerful proof tool for showing that a **collision or repetition must exist**. Hash functions that map a huge set of possible inputs to a smaller set of outputs must have collisions. A sequence of values drawn from a finite set must eventually repeat one.

## Invariants

An **invariant** is a condition that **remains true** at a defined point in **every iteration or recursive step**. Invariants are how you **prove** an algorithm is correct rather than hoping it is. The binary search interval `[lo, hi)` and the monotonic stack's ordering are both invariants.

A **loop invariant** gives a structured proof in three parts:

1. **Initialization**: it holds before the first iteration.
2. **Maintenance**: if it holds before an iteration, it still holds after it.
3. **Termination**: when the loop ends, the invariant, together with the exit condition, **implies the desired result**.

For a loop that finds the maximum of an array, the invariant is "`best` is the largest of the elements seen so far". It is true after looking at the first element, each iteration keeps it true, and when every element has been seen, `best` is the maximum of the whole array.
