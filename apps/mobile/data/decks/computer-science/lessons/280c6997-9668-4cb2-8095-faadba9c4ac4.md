# Graph traversal

Once a graph is represented in code, the next question is almost always some version of "what can I reach from here, and how." Breadth-first search and depth-first search are the two fundamental ways to visit a graph's vertices systematically, and a surprising number of graph problems — finding groups, detecting loops, ordering dependencies — turn out to be small variations on one traversal or the other.

## Breadth-first search

**Breadth-first search** (BFS) explores graph vertices in layers from a start vertex, using a queue (the FIFO structure from the linear data structures lesson). It visits everything one edge away from the start, then everything two edges away, then three, and so on — expanding outward in concentric rings rather than plunging down one path.

```text
graph:        A - B - D
              |   |
              C - E

BFS from A, queue-driven:
  visit A, enqueue neighbors B, C          (layer 1: B, C)
  visit B, enqueue neighbor D, E           (layer 2: D, E)
  visit C, E already enqueued, skip
  visit D
  visit E
order visited: A, B, C, D, E
```

Because BFS finishes an entire layer before starting the next, in an unweighted graph it finds shortest paths measured by edge count: the layer a vertex is first discovered in is exactly its shortest distance, in number of edges, from the start. This only holds for unweighted graphs — with weighted edges, fewer hops does not mean lower total cost, which is why weighted shortest paths need a different algorithm, covered next lesson.

## Depth-first search

**Depth-first search** (DFS) follows one path deeply before backtracking, using recursion or an explicit stack. Rather than exploring breadth-first in rings, DFS commits to a neighbor, then commits to _that_ neighbor's neighbor, and keeps going until it hits a dead end (a vertex with no unvisited neighbors), at which point it backtracks to the most recent vertex that still has unexplored options.

```text
DFS from A (recursive, visiting neighbors in listed order):
  visit A -> visit B -> visit D (dead end, D's neighbors visited) -> back to B
          -> visit E -> visit C (already reachable, but say unvisited) -> back...
order visited: A, B, D, E, C
```

DFS is useful for traversal, cycle detection, topological reasoning, connected components, and exploring paths where layer order is unnecessary — precisely the applications the rest of this lesson works through. Its natural fit with recursion (each call explores one neighbor and recurses) is why it is usually the simpler of the two to implement correctly, even though BFS and DFS visit the same set of vertices overall.

## Connected components

A **connected component** is a maximal set of vertices in an undirected graph where each vertex can reach every other through graph edges. "Maximal" rules out picking a smaller subset when a larger reachable set exists — a component is the whole reachable group, not a piece of it.

Finding connected components is a direct application of either traversal: run BFS or DFS from any unvisited vertex, mark everything it reaches as one component, then repeat from any vertex still unvisited, until none remain. Each traversal run discovers exactly one component.

```text
A - B    C - D    E

Components: {A, B}, {C, D}, {E}
```

## Strongly connected components

In a directed graph, direction breaks the simple "reachable, therefore in the same group" logic — `A` might reach `B` without `B` reaching `A` back. A **strongly connected component** is a maximal set of vertices where every vertex can reach every other, following edge directions both ways. Finding these requires more care than an undirected component search (algorithms like Tarjan's or Kosaraju's handle it), but the underlying tool is still DFS, run in a particular pattern.

## Cycles

A **cycle** is a path through the graph that returns to a vertex already on that path, without immediately retracing the edge just used — informally, a loop you can walk that brings you back to where you started. Detecting a cycle is a natural DFS byproduct: while traversing, if DFS reaches a vertex that is already an ancestor in the current recursive exploration (still "in progress," not merely visited earlier from a different branch), that back-reference is a cycle.

```text
A -> B -> C -> A     (a cycle: A, B, C, back to A)
```

## Directed acyclic graphs and topological ordering

A **directed acyclic graph** (DAG) is a directed graph with no directed cycles — every edge points "forward" in some sense, with no way to follow edges back to where you began. Dependency structures are frequently DAGs: a task cannot (usually) depend on itself, directly or through a chain of other tasks, or the dependencies could never all be satisfied.

A **topological ordering** is an ordering of a DAG's vertices where every directed edge goes from an earlier vertex to a later one in that ordering. Such an ordering only exists when the graph is acyclic — a cycle would force some vertex to come both before and after another, which is impossible to satisfy.

```text
graph:  compile -> link -> run
        fetch-deps -> compile

one valid topological order: fetch-deps, compile, link, run
```

Topological sorting is useful for dependency scheduling, such as build steps, course prerequisites, or jobs that must run only after other jobs — any situation where "do X before Y" constraints need to be turned into one concrete valid sequence. One standard way to compute it is a variant of DFS: run DFS, and prepend each vertex to the output order as its exploration _finishes_ (all its descendants already fully explored) — a vertex that finishes later has nothing left depending on it not yet placed, so it belongs earlier in the final order.

## Common mistakes

- **Using DFS when shortest hop-count paths are needed.** DFS finds _a_ path, not necessarily the shortest one; BFS is the correct tool when "fewest edges" matters.
- **Treating "visited" and "currently on the recursion path" as the same thing during cycle detection.** A vertex reached earlier by a finished branch is not a cycle; only a back-edge to a vertex still open on the current path counts.
- **Assuming a topological order is unique.** Any ordering consistent with the dependency edges is valid; a DAG can have many correct topological orderings.
- **Running topological sort on a graph that is not actually acyclic.** If a cycle is present, no valid topological ordering exists, and the algorithm's output (or failure) needs to be checked, not trusted blindly.

## Key points

- BFS explores in layers using a queue and finds shortest paths by edge count in an unweighted graph.
- DFS follows one path deeply before backtracking, typically via recursion or an explicit stack.
- A connected component is a maximal set of mutually reachable vertices in an undirected graph.
- A strongly connected component is a maximal set of mutually reachable vertices in a directed graph, respecting edge direction both ways.
- A cycle is a path that returns to an already-visited vertex on that same path.
- A directed acyclic graph (DAG) has no directed cycles, which is exactly the condition needed for a topological ordering to exist.
- Topological ordering places every vertex before all vertices it points to, and is the standard tool for dependency scheduling.
