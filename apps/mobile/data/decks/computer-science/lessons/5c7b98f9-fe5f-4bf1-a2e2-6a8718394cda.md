# Measuring algorithms

Before comparing solutions, you need a way to describe how much work they do. Computer science measures algorithms by how their cost grows as the input grows, which lets you reason about performance without running code on every possible machine.

## What an algorithm is

An **algorithm** is a finite procedure that turns inputs into outputs through a defined sequence of steps. "Finite" matters: the procedure must eventually stop. "Defined" matters too: each step must be precise enough that anyone, or any machine, following it gets the same result.

Finding the largest number in a list is a simple algorithm: look at each number once, remember the biggest seen so far, and return it at the end.

## Time and space

Two resources dominate the analysis:

- **Time complexity** describes how the number of basic operations grows as the input size grows. Scanning a list of `n` items once takes time proportional to `n`.
- **Space complexity** describes how much _additional_ memory the algorithm needs as the input grows. The largest-number scan needs only one extra variable, no matter how long the list is.

Both are usually written in asymptotic notation, such as `O(n)`, where `n` stands for the input size.

## Asymptotic notation

Asymptotic notation describes growth for large inputs. It uses three related symbols:

- **Big O** gives an asymptotic **upper bound**. Saying an algorithm is `O(n²)` means its cost grows no faster than some constant times `n²` once inputs are large enough.
- **Big Omega** (`Ω`) gives an asymptotic **lower bound**: the cost grows at least as fast as the stated rate.
- **Big Theta** (`Θ`) gives a **tight bound**: the cost grows within constant factors of the stated rate, both from above and from below.

A linear scan is `Θ(n)`. It is also technically `O(n²)`, because an upper bound only has to be high enough, but `Θ(n)` says much more.

All three notations ignore **constant factors** and **lower-order terms**. A cost of `3n² + 10n + 7` is simply `Θ(n²)`, because for large `n` the `n²` term dominates everything else.

## Why constants are dropped, and why they still matter

Asymptotic analysis cares about the _shape_ of growth. Doubling the input of a quadratic algorithm roughly quadruples its work, whatever the constant in front. That shape decides what happens when inputs become large.

Constants do not disappear from reality, though. Two algorithms that are both `O(n log n)` can differ severalfold in real running time because of memory access patterns, cache behavior, or simply how many instructions each step takes. Big O tells you how an algorithm scales; measurement tells you how fast it actually runs.

## Amortized analysis

Some operations are usually cheap but occasionally expensive. Judging them by their worst single call would be too pessimistic. **Amortized analysis** spreads the cost of the rare expensive operations across a whole sequence of operations, giving a bound on the average cost per operation over that sequence.

This is not an average over random inputs. It is a guarantee: any sequence of `m` operations costs at most `m` times the amortized cost.

## Example: appending to a dynamic array

A dynamic array (such as a JavaScript array or a Python list) keeps a block of memory with some spare capacity. Appending usually just writes into that spare space, which is `O(1)`.

When the block fills up, the array allocates a bigger one and copies every element across. That single append costs `O(n)`.

The trick is **geometric growth**: the capacity is multiplied, commonly doubled, rather than increased by a fixed amount. With doubling, the copies happen at sizes 1, 2, 4, 8, and so on. Across `n` appends the total copying is at most about `1 + 2 + 4 + ... + n`, which is less than `2n`. Linear total work spread over `n` appends gives **amortized O(1)** per append.

```js
// Capacity doubles when full: 1, 2, 4, 8, 16, ...
// Most pushes are a single write; a few trigger a full copy.
const items = [];
for (let i = 0; i < 1_000_000; i++) {
  items.push(i);
}
```

If the array instead grew by a fixed ten slots each time, it would copy roughly every tenth append, and the total work would become quadratic.
