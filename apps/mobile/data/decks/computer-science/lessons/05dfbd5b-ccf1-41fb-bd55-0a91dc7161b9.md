# Graphs

Trees model hierarchies, but many relationships have no single root and can loop back on themselves: road networks, social connections, links between web pages, dependencies between tasks. Graphs are the general tool for all of these.

## Vertices and edges

A **graph** is a set of **vertices** (also called nodes) connected by **edges** that model relationships between entities. Graphs vary in a few important ways:

- In a **directed** graph, each edge has an orientation, pointing _from_ one vertex _to_ another. "Alice follows Bob" does not imply that Bob follows Alice.
- In an **undirected** graph, edges are **symmetric** connections. A two-way road connects both towns equally.
- A **weighted** graph assigns a numeric value to each edge, such as a cost, distance, travel time, or capacity.

## Storing a graph

There are two classic representations. `V` is the number of vertices and `E` the number of edges.

An **adjacency list** stores, for each vertex, the list of edges or neighbors leaving it. It uses space proportional to `V + E`, which makes it **space-efficient for sparse graphs**, those with far fewer edges than possible pairs. Most real-world graphs are sparse.

An **adjacency matrix** is a `V × V` table indexed by pairs of vertices. Each cell records whether an edge exists, or its weight. Checking for a specific edge is **O(1)**, but storage is **O(V²)** even when the graph has few edges, so matrices suit small or dense graphs.

```js
// Adjacency list for a small directed graph
const graph = {
  A: ["B", "C"],
  B: ["D"],
  C: ["D"],
  D: [],
};
```

## Breadth-first search

**Breadth-first search (BFS)** explores a graph in **layers** outward from a start vertex: first the start, then all its neighbors, then all their unvisited neighbors, and so on. It uses a **queue** so that vertices are processed in the order they were discovered.

Because BFS reaches every vertex one edge away before any vertex two edges away, it finds **shortest paths measured by edge count** in an **unweighted** graph. That is why it is used for things like "degrees of separation" or the fewest moves in a puzzle.

## Depth-first search

**Depth-first search (DFS)** does the opposite: it follows one path as deeply as it can, then **backtracks** to the most recent vertex with unexplored neighbors. It is naturally written with **recursion**, or with an **explicit stack** in place of the call stack.

```js
function dfs(graph, vertex, visited = new Set()) {
  visited.add(vertex);
  for (const next of graph[vertex]) {
    if (!visited.has(next)) dfs(graph, next, visited);
  }
  return visited;
}
```

DFS is useful whenever layer order is unnecessary: plain traversal, **cycle detection**, finding **connected components**, reasoning about dependency order, and exploring possible paths.

## Connectivity

In an undirected graph, a **connected component** is a **maximal** set of vertices in which every vertex can reach every other through edges. "Maximal" means you cannot add another vertex and keep that property. A single DFS or BFS from any vertex visits exactly its component.

Directed graphs need a stricter notion, because reaching B from A does not mean you can get back. A **strongly connected component** is a maximal set of vertices where every vertex can reach every other **following edge directions**.

## Cycles and DAGs

A **cycle** is a path that starts and ends at the same vertex, without reusing an edge. A graph with a cycle lets you walk in a loop forever.

A **directed acyclic graph (DAG)** is a directed graph with **no directed cycles**. DAGs are the natural model for dependencies: if task B depends on A, there is an edge from A to B, and a cycle would mean some task depends on itself.

## Topological ordering

A **topological ordering** lists the vertices of a DAG so that **every directed edge goes from an earlier vertex to a later one**. Every DAG has at least one; a graph with a directed cycle has none, since no vertex on the cycle can come first.

Topological sorting is used for **dependency scheduling**:

- Build systems deciding which files to compile first.
- Course planning, where prerequisites must come before the courses that need them.
- Job runners that start a job only after the jobs it depends on have finished.

It can be computed with DFS, by listing vertices in reverse order of when they finish, or by repeatedly removing vertices that have no incoming edges.
