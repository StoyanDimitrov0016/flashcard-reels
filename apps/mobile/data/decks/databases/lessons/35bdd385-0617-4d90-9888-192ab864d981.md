# Relational databases

Almost every application has to remember things: users, orders, messages, payments. You could write that data to files, but the moment two requests change the same data at once, or the server crashes halfway through a write, or someone asks "which customers ordered last week?", files stop being enough. Databases exist to solve exactly those problems, and the relational database is the kind you will meet most often.

## What a database is

A **database** is an organized system for storing and retrieving data while enforcing rules you choose. Those rules usually fall into three groups:

- **Structure**: what shape the data must have, such as "every order has a customer and a positive quantity".
- **Concurrency**: what happens when many clients read and write at the same time, so that one user's change does not silently corrupt another's.
- **Durability**: what survives a crash, so that data the database said it saved is still there after a restart.

Different databases choose different rules. Some enforce a strict structure; others accept any document. Some guarantee that a saved change survives a power loss; others trade that guarantee for speed. The word "database" covers all of them. What they share is that the rules live in the database itself instead of being reimplemented, slightly differently, by every program that touches the data.

## The relational model

A **relational database** stores data in **tables** made of rows and columns, and connects tables to each other through shared values, usually keys.

Each column has a name and a data type. A **row** is one record in a table: one customer, one order, one product. It holds a value for each of the table's defined columns, and every row in a table has the same columns.

```text
customers
 id | name          | country
----+---------------+---------
  1 | Ada Lovelace  | GB
  2 | Grace Hopper  | US

orders
 id | customer_id | total
----+-------------+-------
 10 |           1 | 25.00
 11 |           1 | 12.50
 12 |           2 | 40.00
```

Notice that `orders` does not copy the customer's name. It stores `customer_id`, a value that matches the `id` of a row in `customers`. That shared value is the relationship: order 10 and order 11 both belong to Ada. Relationships are expressed through data, not through pointers or nesting, so the same tables can answer many different questions: all orders for one customer, all customers in one country, total spend per customer.

The set of tables, their columns and types, and the rules attached to them is the database's structure. Later lessons cover how you declare it and what rules you can attach.

## SQL: asking for results, not steps

You work with a relational database through **SQL**, a **declarative** language for defining, querying, and modifying relational data. Declarative means you describe the result you want, not the steps to compute it:

```sql
SELECT c.name, SUM(o.total) AS spent
FROM customers AS c
JOIN orders AS o ON o.customer_id = c.id
WHERE c.country = 'GB'
GROUP BY c.name;
```

This query says "for customers in Great Britain, give me each name and the sum of their order totals". It does not say whether to read `customers` first or `orders` first, whether to use an index, or how to match rows between the two tables. The database decides that. Its **query optimizer** considers the possible strategies and picks an **execution plan**, the concrete sequence of steps it will actually run.

This division of labor is one of the relational model's biggest strengths. The same query keeps working when a table grows from a hundred rows to a hundred million, or when someone adds an index; the database simply chooses a different plan. You will read execution plans in a later lesson, because when a query is slow, the plan is where you find out why.

SQL covers more than queries. The same language defines structure (`CREATE TABLE`, `ALTER TABLE`) and changes data (`INSERT`, `UPDATE`, `DELETE`). Each database adds its own extensions, so this deck uses standard SQL where possible and names PostgreSQL where a dialect matters.

## Key points

- A database is an organized system for storing and retrieving data that enforces chosen rules about structure, concurrency, and durability.
- A relational database stores data in tables of rows and columns and relates tables through shared values such as keys.
- A row is one record in a table, with a value for each of the table's defined columns.
- SQL is a declarative language for defining, querying, and modifying relational data.
- A SQL query states the desired result; the database chooses an execution plan to produce it.
