A time-to-live limits how long a cached entry is reusable. It is a freshness tradeoff rather than
a guarantee that a value always matches the source of truth. Writes may need to invalidate or
update cached entries sooner when the application requires fresher reads.

Use shorter lifetimes for rapidly changing values when stale results matter. Longer lifetimes can
be suitable for stable public content. Never use an old cached authorization decision without
considering the security consequences.
