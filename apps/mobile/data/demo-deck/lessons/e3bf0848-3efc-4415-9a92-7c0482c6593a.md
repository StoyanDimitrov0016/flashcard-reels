# null and undefined

JavaScript has two values for "nothing here", and they are used differently.

<!-- section: cd90b88d-daee-4271-9d51-d2f9f4767957 -->

## undefined

`undefined` is what the language produces on its own when a value is missing:

- a variable that was declared but never assigned;
- an object property that does not exist;
- a function that finishes without returning anything.

<!-- section: c3edcd74-4871-4071-9467-3351b9dd34a3 -->

## null

`null` is a value **you** assign on purpose to say "there is intentionally no value", for
example to clear a selection or to show that a lookup found nothing.

<!-- section: 6409d42e-c306-4f01-a592-5bb8bb01f56c -->

## The practical difference

Both mean "no value", but `undefined` usually means nothing was supplied, while `null` usually
means someone decided there should be nothing. Many codebases keep that distinction so the intent
stays readable.

<!-- section: c6fe6ded-fd17-4c67-9da4-778922b897a1 -->

## A famous quirk

`typeof null` reports `"object"`. This is a mistake from the first version of the language that
was never fixed, because fixing it would break existing websites. To check for `null`, compare
directly:

```js
if (value === null) {
  // value is exactly null
}
```
